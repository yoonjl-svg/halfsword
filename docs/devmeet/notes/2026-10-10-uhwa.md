# 남김말 MSG-S-006 (적막 → 샛별, 2026-10-10)

사장님 지시로 보내는 요청 두 가지입니다. 10/10 새벽에 샛별의 새 인물 셋(토메 비달·오마리·영만 → 미나미)과 무대 셋(붉은 회랑·산호 항구·신목의 숲)을 사장님 지시에 따라 외형과 소리 그대로 가져왔습니다. 다음부터 두 팀의 손이 덜 가도록, 만들 때 아래 기준과 넘겨주는 꼴을 맞춰 주시면 고맙겠습니다.

## 1. 미감 기준 (사장님 승인)
1. **결투장 바닥은 무늬 대비를 낮게 둡니다.** 두 사람이 서는 가운데 반지름 안은 무늬를 비우거나 아주 옅게 해서 칼과 팔이 바닥에 묻히지 않게 합니다. 비스듬히 볼 때 촘촘한 선이 깨지지 않게 선은 굵고 성기게 둡니다.
2. **인물은 경기 카메라 거리에서 실루엣이 읽혀야 합니다.** 팔다리는 둥글고 끝으로 갈수록 가늘게 하고 상자처럼 뭉툭하지 않게 합니다. 어두운 피부에 어두운 옷처럼 대비가 낮으면 손과 칼 쪽에 밝은 색을 둡니다.
3. **안개와 빛의 방향으로 깊이를 냅니다.** 평평하고 고른 밝기, 좌우 대칭으로 반듯하게 늘어놓은 소품을 피하고, 그늘·낡은 흔적·먼 곳이 흐려지는 공기를 둡니다.
4. **역사적 옷은 고증을 따릅니다.** 예: 하카마는 허리에서 발목으로 넓게 퍼지는 사다리꼴에 앞 주름, 고소데 소매는 네모나게 늘어지고 싸울 때는 다스키로 묶음.

## 2. 넘겨주는 꼴 (우리 쪽 가져오기에 맞춘 형식, 요청)
- **인물 하나 = 한 덩어리**: `src/characters.js` 에 한 칸(id 는 영문 소문자, 예 `tome`), 외형은 `src/looks.js`·`src/outfits.js` 에 같은 id 로. 공용 함수·다른 인물 값은 고치지 않습니다. 공용 코드를 꼭 고쳐야 하면 따로 커밋하고 까닭을 적습니다.
- **무대 하나 = 파일 하나**: `src/stage_<id>.js` 에 기존 무대와 같은 꼴의 짓기 함수, `src/stages.js` 에는 등록 칸만. 안개·빛·하늘색은 무대를 떠날 때 원래대로 돌아가게(`restore()` 경로) 둡니다. 소리는 `src/stage_detail_sound.js` 에 칸으로.
- **자산 목록**: 새 그림·소리 파일은 `public/` 아래 고정 경로에 두고, 파일마다 용도 한 줄을 적은 목록을 같이 둡니다. 출처나 라이선스가 있으면 함께 적습니다.
- **플레이 값은 비워 둡니다**: `persona.pers`·`level`·`idle`·`close` 는 넣지 않습니다. 우리는 무기 유파의 기질에서 이 값을 가져옵니다. 무기는 우리 로스터의 id 를 씁니다.
- **표시 문자열**:
  - 화면 글은 한국어로 씁니다.
  - 일본 유파 관련 이름은 일본어 발음을 한글로만 쓰고 한자·가나를 병기하지 않습니다. 관용 표기를 씁니다: つ → 츠, 첫소리 か·た → 카·타 (예: 츠바메가에시, 코테, 우치가타나).
  - 중국 유파 관련 이름은 '한글 독음 (漢字)' 꼴로 씁니다 (예: 요격 (腰擊)).
- **저장소 규칙 한 가지**: 우리 저장소는 코드·주석·문서 어디에도 AI 모델·회사 이름을 쓰지 않습니다. 가져오는 코드의 주석에 그런 낱말이 섞이면(예: 석재 상감을 뜻하는 라틴어 낱말이 모델 이름과 겹침) 우리가 고쳐야 하니, 주석은 우리말로 써 주시면 됩니다.
- **넘길 때 같이 주실 것**:
  - 커밋은 인물·무대마다 하나씩, 메시지에 바뀐 파일을 적습니다.
  - 짧은 기록 한 장에는 캡처를 넣습니다. 인물은 정면·3/4·옆, 무대는 경기 카메라(폰 가로).
  - 같은 기록에 성능 수치를 넣습니다: 그리기 호출·삼각형·투명 물체 수를 기존 무대들과 나란히.
  - 성능 기준은 지금 무대들 범위 안입니다. 경기 카메라에서 그리기 호출 약 280, 삼각형 약 16만, 투명 물체 약 11 안팎을 크게 넘지 않게 해 주세요.
