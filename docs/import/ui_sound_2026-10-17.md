# 첫 화면 · 대기실 소리 — 확인 단추 딸깍 · 첫 화면 바람 (2026-10-17)

- 지시 (사장님 원문): "소리가 없어서 이상해. 첫화면과 대기실에서 확인 류의 단추 누를 때 짧은 효과음 나게 해. 첫 화면에선 바람 소리. 우리가 가진 것중 아무거나 써."
- 새 파일 `src/ui_sound.js` 하나에 소리를 모으고, 덮개(Shadow root)를 가진 `src/game_entry.js` 에서 세 줄로 잇는다. `start_screen.js` · `lobby.js` · `skill_tree.js` 는 손대지 않았다 (단추는 덮개에서 한꺼번에 듣는다 — §2).
- 싸움 소리(`sound.js`)는 그대로다. 게임 묶음(`assets/main-*.js` — main.js 와 그 아래)은 빌드 해시가 바꾸기 전과 같다(바이트 동일).
- 새 녹음 · 새 파일 없음. 새 값은 모두 **사장님 확인 전** (§4). `docs/decisions.md` · `docs/strike/owner_defaults_table.md` 에는 아직 적지 않았다(감독이 모은다).

## 1. 쓴 소리

### 딸깍 — `public/sfx/revolver/insert2.wav` (CC0)

- 출처: AugustSandberg "Revolver Reload" (Freesound 508744, CC0 1.0) — `public/sfx/LICENSE.txt` · `public/sfx/revolver/README.md` 에 이미 적혀 있다. 리볼버 장전에 쓰는 여덟 개 가운데 하나(탄 하나를 넣는 소리).
- 그 파일 안의 **둘째 딸깍**만 쓴다: 0.19 초부터 0.1 초 (딸깍 꼭대기는 0.194 초 · 그 뒤 10 ms 에 −20 dB 로 잦아드는 마른 쇠 딸깍). 앞 2 ms 들어감 · 끝 0.05 초 잦아듦 · 6 kHz 위를 깎아 덜 날카롭게 · 누를 때마다 높낮이 ±3 %.
- 파일은 첫 화면이 뜰 때 미리 받아(31 KB · 누름이 필요 없다) 16 bit PCM 을 그대로 읽는다 — 첫 누름에 바로 난다. 서비스 워커가 `public/` 전부를 담으니 오프라인에서도 같다.
- 고른 까닭: 폰 스피커는 400~500 Hz 아래를 거의 못 낸다. 가진 녹음 가운데 '딸깍'에 가까운 것의 에너지를 재 보니
  - `hit/wood1~5.mp3` (Kenney 나무 두드림) — 1 kHz 아래가 100 % → 폰에서 거의 안 들림
  - `crack1.mp3` — 뼈 부러지는 층으로 쓰는 '찍' 소리라 확인 소리로 맞지 않음
  - `revolver/close.wav` — 딸깍이 두 번(딸-깍)
  - **`revolver/insert2.wav` 둘째 딸깍 — 1~3 kHz 가 72 %, 한 번, 짧다** → 이것
- 작게 틀어 칼집에 칼이 '딸깍' 들어앉는 결로 들린다(총 소리로 읽히는 길이 · 크기가 아니다).

### 바람 — 합성 (게임 무대 바람과 같은 짜임)

- `public/sfx` 에 바람 녹음은 없다. 게임 무대들이 이미 쓰는 합성 바람의 짜임을 그대로 쓴다: 흰 잡음(4 초 · 22050 Hz 되풀이 — `sound.js` `_noiseBuf` 와 같은 꼴) → 띠 거르개 → 위 닫기 → 느린 물결(lfo)로 크기 · 높이 오르내림.
  - 잎 바람 둘 (왼 −0.35 · 오른 +0.35): `sound.js` `_ambTemple` 의 솔바람(900 Hz 띠 · 1.9 kHz 위 닫기)과 같은 꼴, 둘째는 760 Hz · 다른 물결 빠르기
  - 골짜기 바람 (가운데): `_ambTemple` 의 220 Hz 아래 '우우'
  - 층 하나의 꼴(띠 → 위 닫기 → 크기 + 물결 + 좌우)은 `stage_detail_sound.js` `addNoise` 와 같다
- 첫 화면 그림(나무 · 낙엽 · 바람 줄)에 맞춰 무대 바람보다 크게(약 18 dB) 틀되, 잔잔한 바탕이다 — 크기는 §4.

## 3. 바람 — 켜는 때 · 끄는 때

- **켬**: 첫 화면이 떠 있는 동안의 첫 누름(어디든 — `pointerup` · `touchend` · `keydown` · `click`, 보통은 공지 확인). 그 누름 안에서 소리 문맥을 처음 만든다. 누르기 전에는 문맥 자체가 없다(브라우저가 '허락 안 됨' 경고를 남길 일도 없다 — `navigator.userActivation` 이 있으면 누름 안인지 한 번 더 본다).
  - 스며듦 0.8 초. 첫 화면 바람 장면이 불 때(`#entrance` 의 `data-phase` 가 `wind` 가 될 때 — 그림의 바람 줄 · 낙엽이 2.2 초 부는 그때) 1.8 배로 약 0.6 초에 올랐다가 2 초쯤에 걸쳐 제자리 + 잎 바람 높이 +350 Hz. 공지 확인이 첫 누름이면 스며듦과 세짐이 겹쳐 '휘익 — 잔잔' 하나로 들린다.
  - 대기실에서 '첫 화면으로' → 문맥이 이미 있으니 누른 그 자리에서 다시 스며든다.
- **끔**: 첫 화면을 떠날 때(`game_entry.js` `showLobby` — 대기실을 붙이기 바로 앞) 0.8 초에 잦아들고 0.85 초에 소리 노드가 멈춘 뒤 떼어 낸다. 싸움은 늘 대기실 뒤라 바람이 싸움으로 이어질 길이 없다.
- **잠**: 바람이 없고 딸깍도 끝나고 2 초가 지나면 이 문맥을 재운다(`suspend`) — 대기실에 오래 있거나 싸우는 동안 이 문맥은 쉰다. 다음 확인 단추가 누름 안에서 깨운다.
- 화면을 떠나면(앱 전환 · 잠금) 쉬고, 돌아오면 바람이 켜져 있을 때만 다시 켠다. 전화 · 잠금으로 멈춘 문맥은 다음 누름에서 다시 켠다.
- 소리 문맥이 없는 브라우저 · 막힌 문맥(resume 거절)에서는 아무 소리 없이 지나간다 — 오류 · 경고 0 (§5 ⑧).

## 4. 소리 길 · 크기 · 새 값

- 소리 길: 이 모듈의 소리 문맥 → 전체 음량 → 스피커. **전체 음량 = `config.js` `SOUND.volume`(0.8) — 싸움 소리와 같은 값**을 소리를 낼 때마다 읽는다. 0 이면 문맥도 만들지 않는다.
- 소리 끄기 설정: 지금 게임에는 플레이어가 끄는 소리 설정이 없다(main.js '늘 켬으로 고정해 줄을 지운 것 … 소리', 10/10). 생기면 `SOUND.volume` 이나 이 모듈의 `wake()` 한 곳에서 따르면 된다.
- 게임 소리 문맥(`sound.js` `Sound`)을 함께 쓰지 않은 까닭: ① 그 문맥은 싸움을 열 때 만들며 소리 조각 수십 벌 만들기 · 녹음 내려받기가 함께 돈다 — 첫 화면에서 켜면 첫 화면이 무거워지고, 게임 묶음(main.js)을 다 받기 전에는 쓸 수도 없다(첫 공지 확인이 그보다 빠를 때가 많다) ② 싸움 → 대기실 동안 그 문맥은 멈춰 둔다(main.js `toLobby`) — 같이 쓰면 대기실 딸깍이 싸움 배경음까지 깨운다. 그래서 작은 문맥을 따로 두고 음량 값만 같이 쓴다.
- 아이폰 무음 스위치: 싸움 소리와 같게 '재생' 용도로 알린다(`navigator.audioSession.type = 'playback'` — `sound.js` `unlock` 과 같은 까닭. 무음 모드에서도 들린다). 아이폰 깨우기용 1 샘플 무음도 같다.
- 첫 화면 들머리 묶음에 `config.js` 묶음(12 KB · gzip 5.7 KB — 게임 묶음이 어차피 바로 받는 것)이 `modulepreload` 로 붙었다. PWA 새 판 확인은 `<script src>` 만 세므로(`pwa.js` `currentSig`) 영향 없다(아래 §5 game_entry 점검의 PWA 항목 통과).
