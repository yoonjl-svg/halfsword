# 대기실 캐릭터 미리보기 — 진단 (2026-10-17)

- 사장님 원문: "대기실 캐릭터 미리보기가 전투 화면에 비해 아직 해상도 안좋고 엉성해보임. 이유가 뭘까… 그리고 장비 장착 후 다른 각도로 돌리면 크기도 마구 달라져. 근본적으로 지금보다 나아질 방법 없나?"
  → 이어서 "작업 전에 근본적 해결이 어떻게 가능한지/불가능한지부터 진단해. 안 될 거 같으면 저 창을 없앨 수도 있어."
- 상태: **진단만**. 코드는 바꾸지 않았다. 아래 '시안'은 브라우저 페이지 안에서 미리보기 장면의 설정만 바꿔 다시 그려 본 것(저장소 코드 그대로).
- 바탕: main 32ba623 · 배포판(vite build + PWA). 폰 흉내 = 가로 844 × 390 · 세로 390 × 844 · 화소 비 3 · 터치. 소프트웨어 GL 이라 ms 값은 실기기 값이 아니라 판끼리의 비.

## 1. 한 줄 결론

- **돌리면 크기가 바뀌는 것**: 원인이 코드 한 곳(틀 맞춤 `fit()`)이라 **완전히 고칠 수 있다** — 작은 일.
- **해상도 · 엉성함**: 그리는 화소는 원인이 아니다(대기실이 싸움 화면보다 더 촘촘하다). 원인은 빛 · 톤 · 카메라 · 그림자 · 크기 · 카드 바탕 — 모두 미리보기 쪽 설정이라 **대부분 고칠 수 있다**(작음~중간). 다만 **몸 모델 자체의 단순함**(상자 몸통 · 원기둥 팔다리)은 미리보기에서 못 고친다 — 가까이 정면에서 보면 싸움 화면(멀리 · 뒤에서 · 움직임 · 무대 속)보다 더 드러난다.

## 2. 왜 '해상도 낮고 엉성해' 보이나 — 잰 값

| | 대기실 미리보기 (`src/lobby_character.js`) | 싸움 화면 (`src/main.js`) |
|---|---|---|
| 그리는 화소 (폰 가로 · 화소 비 3) | 칸 156 × 252 CSS → **468 × 756** (화소 비 min(기기, 3) = 3 · 늘림 없음) | 844 × 390 → **1688 × 780** (상한 2) → 화면에서 **1.5 배 늘림** |
| 몸 키 (화면) | 179 CSS px (0°) · 나뭇가지 90° 면 124 CSS px | 225 CSS px (판 시작 뒤 어깨 너머 자리) |
| 계단 펴기 | 있음 | 있음 |
| 톤 매핑 | **ACES Filmic** — three 안에서 노출 × 1/0.6 = 1.67 배 뒤 곡선 | **없음** (sRGB 출력은 같음) |
| 빛 | 반구 **2.4** + 앞빛 **3.0** + 뒷빛 1.5 (그림자 없음) | 반구 **1.2** + 해 **1.7** (바닥 그림자) |
| 카메라 | **정사영** · 눈높이 정면 | 원근 55° · 2.3 m 높이 · 3 m 뒤 |
| 바탕 | 카드 바탕 **픽셀 무늬**(32 × 64 그림을 픽셀 확대 — '겉은 픽셀') | 3D 무대 |
| 몸 · 옷 · 재질 · 손 | 싸움과 **같은 Fighter**(`src/lobby_rig.js` — 같은 겉모습 · 재질 · `hands.js`) | 같음 (싸움에만 붙는 것은 오라 · 칼 잔상 · 밤 무대 캐릭터 빛 — 낮 무대에선 0) |

- **화소는 원인이 아니다**: 같은 기기 화소 배율로 잘라 맞대면 대기실이 오히려 더 또렷하다(싸움은 2 배로 그려 3 배 화면에 늘림) — `docs/handoff/lobby_preview/lobby_vs_battle_sharpness.png`.
  사장님 폰이 화소 비 1 이던 옛 판일 가능성도 없다: 360° 돌림판(10/16 08:3x)이 보인다면 화소 비 3(10/16 04:5x)이 들어간 뒤 판이다.
- 실제 원인 넷:
  1. **빛이 싸움의 약 2 배 + ACES** → 옷이 허옇게 바래고 납작하다. 같은 몸 · 같은 각 · 같은 화소 자리의 옷 밝기 **201 → 싸움 빛으로 141**, 채도 **0.23 → 0.28** (`light_experiment_030.png`).
  2. **정사영 정면 + 그림자 없음** → 종이 인형처럼 납작하고 떠 보인다. 상자 몸통 · 원기둥 팔다리가 그대로 드러난다.
  3. **칸 안에서 작다** — 칸 높이 252 CSS px 에 몸 179 px(0°), 칼을 옆으로 돌리면 124 px.
  4. 캐릭터 **바로 뒤 카드 바탕의 큰 픽셀 무늬**가 '해상도 낮음'으로 읽힌다(투구 확대 사진의 뒤 칸).

## 3. 왜 돌리면 크기가 바뀌나 — 코드 자리

- `src/lobby_character.js` `fit()` 를 `render()` 마다 부른다. 몸 · 무기 메쉬 상자(AABB)의 바닥 모서리 점을 그 각에서 화면 가로로 투영해 폭을 재고,
  칼이 옆으로 뻗어 폭이 넓어지면 **화면 반높이 `half` 를 `ZOOM_OUT`(1.6 배)까지 키워 물러나고**, 화면 가운데 `cx` 를 칼 쪽으로 옮긴다. 상자 꼭짓점이라 비스듬한 나뭇가지는 실제보다 넓게 잰다.
- 잰 값(나뭇가지 장착 · 폰 가로 · 그리기 화소):

| 각 | 0° | 45° | 90° | 135° | 180° |
|---|---|---|---|---|---|
| 몸 키 (px) | 538 | 456 | **371** | 467 | 538 |
| 머리 위 (px) | 161 | 243 | 327 | 232 | 161 |

  — 90° 에서 **−31 %** · 왼쪽 끝 128 → 13 px 로 밀림. 세로 화면도 487 → 343 px(−30 %). **빈손은 모든 각에서 559 px 그대로** — 무기 폭이 원인.
- 장착 때만 바뀌는 몫도 하나: `display = max(무기까지 포함한 키, 2.16 m)` — 칼을 머리 위로 드는 무기면 모든 각에서 몸이 작아진다(나뭇가지는 해당 없음).

## 4. 근본 해결 — 가능한가 · 어떻게 · 값

| 원인 | 판정 | 방법 | 일 |
|---|---|---|---|
| 돌리면 크기 바뀜 | **가능** | 틀 고정: 축척 = 몸 키(한 번만 정함 — 무기 · 각과 무관) · 돌림판 축 = 화면 가운데. 시안에서 머리 위 135~137 px 로 각마다 그대로 (`mock_fixed_framing.png`) | 작음 |
| 빛 · 톤 | **가능** | 싸움과 같은 그리개 설정(톤 매핑 없음) · 같은 빛 꼴(반구 1.2 + 해 1.7 — 어두운 카드 위라 보조광 조금은 맞춰 봄) | 작음 |
| 납작함 · 떠 보임 | **가능** | 원근 카메라(화각 약 30° · 조금 위에서) + 발밑 그림자 | 작음~중간 |
| 작음 | **가능** (칸 크기 안에서) | 틀 고정으로 몸이 늘 칸 높이의 약 75 % (지금 0° 71 % · 90° 49 %). 그보다 크게는 칸(156 × 252 CSS) 자체를 키우는 배치 일 | 작음 |
| 카드 바탕 픽셀 무늬 | 가능 (디자인 결정) | 캐릭터 뒤만 매끈한 바탕 — '겉은 픽셀, 속은 매끈' 규칙 안에서 사장님이 고를 것 | 작음 |
| 몸 모델의 단순함 | **미리보기로는 불가** | 캐릭터 모델 자체 일 — 싸움에도 같이 바뀜 · 이번 범위 밖 | 큼 |

- 칼끝: 틀을 고정하면 칼을 옆으로 돌렸을 때 칼끝이 칸 밖으로 나간다. (가) 그대로 자름(사진기처럼 — 권함) · (나) 칸 틀 밖으로 넘쳐 보이게 · (다) 장착할 때 한 번만 '360° 다 들어가는 크기'(돌릴 땐 그대로, 장착을 바꾸면 바뀜) — 사장님 고를 것.
- 값(시안 — 소프트웨어 GL): 그리기 0.4~0.8 ms · 그리기 호출 60 → 그림자 넣으면 108 · 삼각형 7.8 천 → 15 천 · 그림자 지도 1024² 하나(약 4 MB). 돌릴 때 · 장착을 바꿀 때만 그리므로 가만히 있을 때는 0.
  지금 그대로 값(`tools/browser/lobby_preview_cost.mjs` 5 번): 그리기 화소 468 × 756 = 353,808 · 호출 41(빈손) · 한 번 그리기 1.1 ms · 미리보기 준비 63 ms(가운데). 그리개 둘째 문맥의 화면 버퍼는 계단 펴기 4 배 포함 어림 14 MB.
- 그리개 하나를 같이 쓰기 vs 따로: **따로 둠을 권함**. 싸움 그리개는 대기실 동안 멈춰 있어(`main.js` frame — `html[data-start-open]`) 같이 쓰려면 싸움 캔버스에 그려 카드로 옮기거나 캔버스를 옮겨야 한다 — 싸움 그리기를 건드리는 일(위험 · 중간~큼). 얻는 것은 어림 14 MB · 준비 63 ms 정도.

## 5. 창을 없애면

- 고칠 곳: `src/lobby.js`(미리보기 만들기 · 장착/해제 · 스킬북 바뀜 → 걸음 자세 · 닫기) · `src/lobby.css`(세 칸 배치가 캐릭터 카드 크기 `--card-w/--card-h` 에서 셈 — 출발 단추도 카드 밑) · `src/lobby_character.js` · `src/lobby_rig.js`(통째로 지움) · `src/main.js` `lobbyRigSpec` · 브라우저 시험 · 사진 도구 17 개(`tools/browser` 16 + `tools/ui/ui_unify_mock.mjs` — `#characterView` · `lobbyPreview` 를 '대기실이 열렸다' 신호로도 씀) · 시뮬 둘(`tools/sim/lobby_rig.test.mjs` · `lobby_rig_probe.mjs`).
- 잃는 것: 출발 전에 장착 모습 확인(케틀 햇 쓰고 벗기 · 무기 쥠 · 겨눔이 싸움과 같은 몸) · 사장님이 정한 360° 돌림판(10/16 08:3x) · 나중 '동작 재생'(`docs/import/ui_fix_2026-10-16.md` §7 — 이 몸 위에 만들 계획).
- 얻는 것: 그리개 둘째 문맥 없음(어림 14 MB) · 장착 때 자세 잡기 물리(최대 6 s 를 화면마다 8 ms 씩) 없음 · 대기실 여는 값 약 63 ms 줄음 · 배치 단순.
- 가운데 길: 3D 를 한 장짜리 그림(장착이 바뀔 때 한 번 그린 초상)으로 — 360° 는 잃고 장착 모습은 남는다.
