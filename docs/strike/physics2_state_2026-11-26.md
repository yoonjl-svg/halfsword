## 6. 감사 지시의 요점

- 대본 먼저(조각별 켜고 끄기 표) · 일꾼끼리의 말싸움 대신 대본으로 확인 · 읽는 이는 diff + 닿은 파일 + 결과 표만.
- 과업 합계가 100만을 넘거나 가늠을 절반 넘게 넘길 것 같으면 묶음 앞에 다섯 줄(목표 · 가늠 · 일꾼과 모델 · 확인 · 멈춤) · 답 또는 10 분 기다림 · 끝나면 합계 한 줄.
- 값은 일꾼이 손으로 돌려 보지 않는다 — 값 훑기 대본을 짓고 CPU 가 찾는다.
- 고쳐 쓰기 · 지적 반영은 새 일꾼이 아니라 지은 일꾼에게 되돌린다.
- 긴 훈련을 기다리는 데 토큰을 쓰지 않는다 · 진행을 들여다보는 호출을 되풀이하지 않는다.
- 시험 가르기는 "깨진 시험 → 그 도우미를 씨앗 N 개로 돌리는 한 대본"을 내가 먼저 짓고, 표로 안 갈리는 것만 일꾼에게.

     → 설계 검토가 끝나면 고침 일꾼에게 검토 지적과 함께 넘김(적어 둔 곳: 작업장 p2/r11/audit_points.md). 온몸 베기 시험 일꾼에게는 이미 전함(변형마다 닿는 시간 · 손을 늦추지 않는 변형 추가 · 몫은 읽는 값).
  4. 뛰기 짓기: 단계 차례를 도구 → 제자리 뜀 → 2.5 → 3.5 → **서기 · 돌기** → 가장 빠른 값으로. 과녁은 "싸움에서 쓰는 뛰기"(3.5 m/s 에서 서고 돌면 본판에 넣을 수 있음), 천장은 덤.
  5. 뛰기 짓기: 첫 구조 단계가 "코드 지도"(r10_run_codemap.md · 두 쪽)를 남기고 뒤 단계는 지도와 고칠 함수만 읽음.
     → 대본을 고쳐 둠. 도구 단계가 끝나 둘째 단계가 시작되면 멈추고 고친 대본으로 이어 돌림(끝난 단계는 다시 돌지 않음).
  - 자료 조사 정리에 물음 하나 추가("무엇이 먼저 떠나는가 — 손 · 몸 · 발, 몸통과 다리의 몫은 실제로 얼마인가"). 정리 단계가 시작되면 고친 대본으로 이어 돌림.
