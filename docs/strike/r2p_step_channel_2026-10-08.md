# R2′ 걸음 조율 채널 — "걸음이 몸을 싣게" 설계 (2026-10-08 13:35~13:41, 디렉터; 사장님 12:05 3] "chain legs(A) 를 기본 후보로 두고 걸음 조율 채널을 설계해도 되는지 → 그렇게 해")

읽는 법: §1 이 결론, §2 가 오늘 잰 사실, §3 설계, §4 목표·관문, §5 일정·여쭐 것. 수치는 전부 `docs/strike/owner_defaults_table.md` 181~183(사장님 확인 전).

## 1. 결론(먼저)
- **legs(발 힘쌍 A)는 오늘 그대로 기본으로 못 올린다**: 선 채 베기에서 골반이 명령보다 0.3~0.55 rad 뒤처져(엉덩이 근육이 핀 박힌 발 마찰 안에서 못 돌림) **베는 자리가 깨진다** — AI 첫 베기 25 → 8/30, 대본 사선 빗나감(§2 표). 10/7 명세 재측정의 G5·G7 실패와 같은 뿌리.
- 그래서 **걸음 조율 채널이 legs 의 전제**다: 베는 동안 골반을 돌리는 힘을 '서서 비트는 엉덩이' 가 아니라 **내딛는 걸음의 발 밀기(땅 반작용 × 발의 옆 치우침 = yaw 짝힘)** 에서 얻는다. 사람 검술이 그렇다(오른쪽 위 베기 = 오른발이 밀고 왼발이 나간다).
- 채널 셋: **(A) 밀기 자리**(`GAIT.pushAtFoot`: 걷기 추진력을 골반 중심이 아니라 딛은 발 자리에 건다 → 짝힘이 저절로) · **(B) 발 고르기**(획 방향의 반대 발이 나간다 = 획 시작 쪽 발이 민다; 획 시작 때 1.3~2.4 m 면 자동, 오늘 lunge 자리) · **(C) 밀기 세기**(베는 걸음의 밀기 240 N → 후보 ×1.5~2, 측정 뒤). AI 도 같은 규칙(기술 길의 가로 부호로 발 고르기).
- 구현 순서 A → 측정 → B(+AI) → 측정 → C → legs 기본 판정. 각 단계 기본값 바이트 동일(깃발 0).

## 3. 설계
### 3-A. 밀기 자리 `GAIT.pushAtFoot` (0 = 오늘, 후보 1; 확인표 181)
- 걷기 추진력(수평 fx·fz, 크기는 오늘 식 그대로: M·moveAccel·Δv, 상한 M·maxAccel)을 골반·가슴 중심 대신 **딛은 발 자리(발 x·z, 골반 높이)** 에 하중 비율(footLoad F/B)대로 건다: `pelvis.addForceAtPoint(F_k, (foot_k.x, pelvis.y, foot_k.z))`. 세기·방향은 같고 **점만** 옮기므로 직진 가속은 그대로, 발이 몸 중심선에서 옆으로 d 만큼 치우친 만큼 yaw 짝힘 F·d 가 **저절로** 생긴다(오른발이 밀면 왼쪽으로 돈다). 가슴 몫(upperShare 0.15)은 그대로 가슴 중심에(상체 꺾임 방지 몫이라 점을 옮기지 않음). 섞기: 값 p 로 (1 − p) 중심 + p 발 자리.
- 두 발 다 딛고 서 있을 때 좌우 대칭이면 짝힘이 서로 지워져 오늘과 같다 → 선 채 돌진은 안 바뀐다. 한 발만 딛었거나 하중이 치우친 순간(내딛는 중)에만 돈다 = 사람과 같다.
- 위험: 핀 마찰 한계(pinFeet, 확인표 127)가 그 짝힘의 반작용을 받아야 한다 — 밀기 240 N × d 0.15 = 36 N·m 는 한도 안(두 발 40~80). 넘어짐·핀 미끄러짐은 관문.

### 3-B. 발 고르기 + 발사(베는 걸음) — 확인표 182
- **규칙**: 획 방향(fighter.swingDir, 손 목표 가로 속도 부호 — 묶음과 같은 신호)이 정해진 순간, 1.3~2.4 m(오늘 lunge 창 `SKILL.lungeMin/Max`, 새 수 아님) 안이면 `gait.requestStep({ kind: 'pass', leg: 획 반대쪽 발, fwd, duration: 0.3(= lungeTime) })`. 오른쪽에서 왼쪽으로 베면(swingDir < 0) **왼발이 나가고 오른발이 민다**; 왼쪽에서 오른쪽이면 반대; 세로 획(swingDir 0)은 앞발 그대로(오늘 frontLeg 규칙). `requestStep` 에 `leg` 선택지를 더한다(오늘은 gait 가 고름).
- **오늘 lunge 와의 관계**: anchor 의 lunge(skill.js 627: 창 안이면 0.3 s 동안 move.y ≥ 0.9 → 밀기 240 N, 걸음은 gait 가 알아서)는 **발을 고르지 않고 밀기만** 한다. legs 에선 꺼 두었다(확인표 126). 채널 B 가 그 자리를 대신한다: legs 에서 lunge 를 다시 켜되 `requestStep(leg)` 로. anchor 에선 오늘 그대로(바이트 동일), 깃발 `GAIT.cutStep` 0/1.
- **박자**: 획 시작 때 부탁 → gait 가 뗄 발의 하중을 옮기고(liftLoad 0.35·liftWait 0.1) 발을 든다 → 딛은(미는) 발 하중이 커지는 그 0.1~0.2 s 가 베기의 몸 돌림 구간(가슴 ω 최고가 칼끝 최고보다 100~160 ms 앞)과 겹친다. 맞는지는 장부로 잰다(§4 G-S3).
- **AI**: `ai.gaitStep()` 이 `tech.path` 의 가로 부호(끝 x − 시작 x)로 같은 발을 고른다. stepTime(짧으면 안 내딛음)은 그대로.

### 3-C. 밀기 세기(베는 걸음만) — 확인표 183
- 사람의 베는 걸음 발 밀기는 걷기(240 N)보다 세다(0.5~1 × 몸무게 수평 성분, 짧게). 후보: 베는 걸음(cutStep) 동안만 밀기 상한 ×1.5~2(= 360~480 N, yaw 짝힘 54~96 N·m → 필요 몫 90 에 닿음). **측정 뒤에 정한다** — A+B 만으로 G-S1 을 넘으면 C 는 없음.

### 3-D. 묶음(호)과의 관계
호(가슴 명령 −x·0.35·(1 + 2·act))는 그대로. legs 에선 가슴이 골반에 대해 돌고 골반은 걸음 짝힘이 돌린다 → 둘이 같은 방향(획 반대 발이 나가므로 자동)이면 더해지고, 걸으며 벨 때 호가 깎이던 것(16.7 → 14.9)이 사라져야 한다(G-S2). anchor 에선 닻 모터가 골반을 돌리므로 A·B 는 '보이는 걸음' 만 보태고 숫자는 거의 그대로일 것(측정으로 확인, anchor 는 기본 꺼 둠).

## 4. 목표("90 %")와 관문 — 모두 legs + 묶음 v2 + 채널
- G-S0 **자리**: AI 첫 베기 명중 ≥ 22/30(오늘 anchor 25, legs 8), 대본 1.35 m 세로 머리·사선 가슴 둘 다 맞음(legs 오늘 가슴 72 / 빗나감).
- G-S1 **속도**: 대본 롱소드 사선 선 채 ≥ 16.7(anchor 묶음), 걸으며 ≥ 선 채(오늘 14.9 < 16.7); 모르겐슈테른 걸으며 ≥ 10.3.
- G-S2 **골반이 간다**: 골반 ω 최고(대본 사선) legs 오늘 94~169 °/s → ≥ anchor(227), 사람 범위 ≤ 750; 순서 골반 → 가슴 → 손 → 칼끝(명세 G5, 10/7 legs′ 실패 +159 ms → −130~−40).
- G-S3 **짝힘 출처**: 장부에 발 밀기 × 치우침(yaw 짝힘) 열 추가 — 베기 동안 골반 각운동량 변화의 ≥ 50 % 가 땅 짝힘(명세 G2 잔차 r_z 38 → ≤ 20 N·m).
- G-S4 **안전**: 36 결투 넘어짐 ≤ anchor + 2/36, 핀 미끄러짐(G11) ≤ anchor, NaN 0, fights12(legs 기본) dead 소음 폭 안.
- G-S5 **불변**: 깃발 0 = 바이트 동일(fights12 `8d574a8c`·live `7e4587f3`·finish `d4d463b3`·corr IDENTICAL).
- 체감: 사장님 플레이(`?r2p=legs` 가 채널까지 켜게 바꾼다).

## 5. 일정·여쭐 것
- A(pushAtFoot, 1 h) → 측정 30 분 → B + AI(1.5 h) → 측정 → C(필요하면) → legs 기본 판정(사장님). 오늘 저녁 안에 A·B 까지.
- 여쭐 것(≤ 3): ① 베는 걸음의 밀기를 240 N 넘게(후보 ×1.5~2) 둬도 되는지 — 측정이 요구할 때만. ② legs 에서 '획 시작 때 자동 걸음(발 고르기)' 을 켜는 것(anchor 의 lunge 와 같은 창 1.3~2.4 m) — 손가락 입력에 걸음 채널이 따로 없으니 자동이 맞다고 봄. ③ legs 기본은 G-S0~S4 를 넘은 뒤에만 — 동의하시는지.

## 6. 구현·계측 결과(10/8 13:44~13:55) — A·B 는 들어갔고(깃발 0 = 바이트 동일), 효과는 작다: 뿌리는 걸음이 아니라 엉덩이 → 발 사슬의 누수

왜 작은가(디버그 `cutstep_dbg`, 선 채 사선 1.6 m, 걸음 부탁 수락·왼발이 0.3 s 에 1 m 나감): 베기 동안 골반 yaw(머리 방향 기준)는 A 끔 −0.42 → A 켬 −0.34 → **추진력 ×3 이면 −0.17**(칼끝 최고 때) — anchor 의 닻 모터는 같은 때 **+0.27**. 즉 발 자리 밀기는 골반을 돌리긴 하나(채널 설계대로 짝힘이 생긴다) 오늘 걷기 밀기(≤ 256 N × 옆 치우침 0.11 m ≈ 25 N·m)로는 필요 몫(≈ 90 N·m)의 1/4 이고, ×3(≈ 770 N, 사람 베는 걸음 상한)이라야 절반에 닿는다. 나머지 절반은 **엉덩이 비틀기 토크가 골반 회전으로 안 가는 누수**(명세 10/7 G2b 싱크 0.047: τ̂ 266 N·m 중 골반 I·α 몫 5 %) — 허벅지 비틀림·무릎·발목·핀 미끄러짐으로 샌다. 걸음 채널은 그 누수를 못 메운다.

판정: ① legs 기본 후보는 **보류**(확인표 122) — 걸음 채널 전제가 아니라 사슬 누수(K1) 해결이 전제. ② A·B 는 실험 깃발로 남긴다(`?r2p=legs`, 바이트 동일). ③ C(밀기 세기 ×3)는 골반을 절반 돌리지만 걸음이 과하게 나가(골반 +0.36 m, 뒤이어 yaw 0.65 로 과회전) 단독으론 쓸 수 없다 — 사슬 누수를 먼저. ④ 측정 조건 교정: 대본 장면(step_strike·gauge)은 시작 정지(ARENA.startHold 2 s) 안에서 베어 기술 걸음·lunge 가 **거절**된다(`feetHeld`) — 걸음이 든 측정은 `ARENA.startHold=0` 으로(이 표가 그렇다); 오늘까지의 대본 수치는 모두 '걸음 없는 베기' 였다. 시간 13:41~13:55(예상 30~40 분).
