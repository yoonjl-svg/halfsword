## 2. 바꾼 것 · 왜 짜임으로 맞나 (src/fighter.js)

한도의 차례: 어깨 밧줄(몸의 단단한 묶음 — 밧줄 안 돌림이 하나라도 있으면 밖을 명령하지 않음) → 위팔 돌림(참 돌림 수 — 들림 지름길 없이, 사람 팔 범위를 보는 팔만) → 팔꿈치 줄 아래 → 손목 고름.

1. **밧줄 호 (ropeArc · ropeOff · ropeGo)**: elbowSwivel 이 들어오자마자 돌림 원을 찾기와 같은 2°(SW_STEP — 있던 STEP 을 한 값으로 모음) 씩 보아, 지금 돌림 th0 에서 위팔이 밧줄 안인 채 갈 수 있는 몫 [th0 − lo, th0 + hi] 를 잰다. th0 가 밖이면(손이 움직여 호가 옮겨 옴) 먼저 가장 가까운 밧줄 안 돌림으로 옮긴다. 모든 찾기(armOk)는 이 호 안만 보고, 따라감은 want 까지의 호 안 몫(ropeOff)만큼 간다. want 는 th0 에서 호 안으로 닿는 돌림이고 찾기는 한쪽 180° 까지라 가는 길이 짧은 쪽이며 그 길 전체가 호 안이다 — **밧줄 안 돌림이 있으면 elbowSwivel 이 돌려준 돌림은 밧줄 안**(2° 보다 좁은 막힌 조각만 예외). 밧줄이 없으면 호는 원 전체 · ropeOff = 짧은 쪽이라 본판과 같은 셈.
2. **기본 겨냥 z0 (ropeHome)**: 0 으로 못 가면(밧줄 밖) 갈 수 있는 돌림 가운데 0 에 가장 가까운 것 — ropeSwivel 이 0 을 옮기던 자리이자 본판에서 몸이 밧줄에 막혀 서던 자리. elbowSwivel 의 '기본 겨냥 0' 자리를 모두 z0 로. 밧줄이 0 을 안 막으면 z0 = 0 (본판 그대로). z0 ≠ 0 은 사람 팔 범위의 '0 은 늘 됨' 을 받지 않는다.
3. **사람 팔 범위 팔의 물러남 (swivelHumanRope)**: armOk 돌림이 호 안에 없을 때만 — 호 안에서 th0 에 가장 가까운 ① 참 돌림 안 · 팔꿈치 줄 아래 ② 참 돌림 안 ③ 팔꿈치 줄 아래 · 없으면 th0. 참 돌림 = armTwistOk 의 셈을 들림 지름길 없이(armTwistIn 으로 나눔 — armTwistOk 는 같은 셈 그대로). 두손 칼(human false)에는 안 넓힘.
4. **ropeSwivel**: 위팔 돌림 고름(ropeTwistOk)을 빼고 가장 작은 |θ| 만. θ = 0 이 밖이므로 0 에서 가장 가까운 안 자리는 겹침의 경계, 곧 어느 호의 끝 — 꼭대기 · 같은 곳 후보는 밧줄 안 돌림이 없을 때만 이김(재기 F2 다른 고름 0). 스텝마다 만들던 함수(m) · 배열(for … of [[…]]) 을 모듈 자리 배열(_rsC)과 함수(ropeMin)로. 일찍 나감 문턱을 후보와 같은 반올림 몫(−1e-9)으로.
5. **되써넣기**: 그대로 두었으나 팔꿈치 돌림 길에서는 밧줄 안 돌림이 없는 자세에서만 돌림이 0 이 아니다(12 판 9 / 69 775 스텝 · 막기 537 / 50 400 — 하나 빼고 모두 1° 훑음으로 밧줄 안 없음). 그때 명령한 팔꿈치 자리를 돌림 각에 두어 다음 스텝이 거기서 잇는다. 예외 하나: 밧줄 안 호가 2° 보다 좁으면 elbowSwivel 은 '밧줄 안 없음'으로 보고 ropeSwivel 이 그 호로 돌린다(12 판 1 스텝 · 92°). 고정점이 생기던 길(막힌 호로 들어간 따라감)은 1 로 없어짐.
6. **주석 (F7)**: ① ropeSwivel 머리말 — 후보 여덟과 고름이 늘 끝인 까닭 ② 'armOk ③ 과 같은 잣대' — ropeTwistOk 와 함께 지움 ③ '돌림 0 은 늘 됨' → 밧줄 안으로 갈 수 있으면 · z0 ≠ 0 은 ①②③ 봄 ④ elbowSwivel 머리 '이미 한도 안이면 아무것도 안 바꿈' → 밧줄 밖이면 밧줄 안으로 ⑤ best 줄 — 씨앗을 armOk(th0) 로 바꾸고 주석을 코드대로 ⑥ '스텝마다 새 함수 · 배열 없음' — ropeSwivel 의 함수 · 배열, elbowSwivel 의 ropeOk 함수를 모두 모듈 함수로 (새 코드에 스텝마다 만드는 함수 · 배열 없음. 본판에 있던 elbowSwivel 의 dev · armOk 등 함수와 `n ? [1, -1] : [1]` 은 그대로).

두 번 설계: ⓐ (1 · 3 · 4 · 5) — 12 판 몸 돌림 밖 3.42 % · 튐 14 · 밧줄 밖 69 · 마무리 109. ⓑ ⓐ + 2(z0) — 아래 '지금'. 막기 줄 두손 '0 이 밧줄 밖' 갈래에서 고른 돌림의 돌림 밖이 63 % 로 그대로라(그 갈래 want 가 z0 인 것 20 % — 손목 고름이 z0 를 넘김) 몸 돌림 밖은 크게 안 바뀜.

- ② **kote 허공 수**: 칼끝 길 −55 % · 걸린 시간 −46 % (11/16 대비 · 앞 HEAD 는 −7 % · +25 %). 거둠 꼬리가 짧아진 것인지 볼지.

## 확인 안 한 것

- 씨앗 3 이상 · estoc · sabre — 규칙대로 안 잼.

- 2° 보다 좁은 막힌 조각을 따라감이 지나는 경우 · 2° 보다 좁은 밧줄 안 호(12 판 1 스텝 — ropeSwivel 이 92° 돌림): 풀이 해상도 몫이라 셈으로 막지는 않음.
- 몸 돌림 밖 갈래 표의 본판 값 (본판에는 재기 고리를 안 넣어 갈래를 못 나눔 — 몸 · 명령 수만).
- kote −55 % 의 까닭 · ai_intercept 덮는 맞받기 0 의 까닭 (쫓지 않음).
- 왼손잡이(side −1) — 이 빌드에 없음.
