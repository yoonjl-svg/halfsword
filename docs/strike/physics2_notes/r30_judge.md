## 바뀐 것

- `LEG_JUDGE = { limit: 312.5, ecc: 1.3, eccW: 1 }` (주석에 사장님 말씀).
- `legAllow(tau, wRel)` — 배율 1 ~ 1.3. tau = 먼 쪽(자식) 묶음이 관절로 받은 토크. 지금 길이를 재는 바로 그 벡터를 쓴다 (요구 = 모터 다시 셈 + 명시 토크 · 잰 값 = meas · 무릎의 잰 값은 이미 축으로 줄인 것). wRel = 자식 − 부모 각속도, 스텝 앞 값 (도구가 이미 적어 두는 `prev.w`).
- 부호: 게임 `clampLeg(t, w, …)` 의 t 는 부모 쪽 토크, 자식은 −t 를 받는다. 그래서 심판 벡터로는 `dot(tau, wRel) < 0` 이 늘어남이다. wEcc = −(tau 방향 · wRel).
- 요약 칸: `limit` 은 그대로 기준 수(다리 312.5). `overShare` · `measOverShare` 는 늘어나는 몫을 곱한 한도로 센 몫. 다리에만 `overBaseShare` · `measOverBaseShare`(312.5 그대로 센 몫)를 더했다. 그 밖 칸 · 줄은 그대로.
- 보고 줄: 다리 칸은 `(새 몫%/312.5 몫%)` 로 둘 다 보인다. 예: `thighB 235/312.5(0.2%/0.2%)`.
- `legJudge` 칸 + `legJudgeCheck()` (config `LEGS.limit.hipFlex · kneeExt · anklePlantar` · `LEGS.ecc` · `LEGS.eccW` 와 견줌 · 읽기만). 다르면 `경고: 심판의 다리 잣대가 몸 값(config LEGS)과 다름 — …` 한 줄.
- 엿보기 `globalThis.__honestyLegDbg` (다리 표본마다 부름 · 읽기만). 이미 있는 `__honestyDbg` 와 같은 꼴. 켜고 끄는 값이 아니고 셈을 바꾸지 않는다. V2 · V3 대본이 이것으로 같은 스텝의 게임 값을 읽었다.

## 여쭐 값

- **312.5 N·m** — 엉덩이 · 무릎 · 발목 한도. 몸 값 `LEGS.limit` 의 hipFlex · kneeExt · anklePlantar 를 옮겨 적음 (사장님이 정하신 값).
- **1.3** — 늘어나며 버티는 근육의 한도 배율. 몸 값 `LEGS.ecc` (사장님이 정하신 값).
- **1 rad/s** — 이 빠르기에서 배율이 다 참. 몸 값 `LEGS.eccW` (사장님이 정하신 값).
- 내가 고른 것 (여쭙니다):
  - 한 수로 세 방향을 다 잰다. 심판은 관절 토크 벡터의 길이 하나와 견준다. 몸은 굽힘 · 벌림 · 돌림 축마다 다른 한도(예: 무릎 굽힘 162.5 · 발목 발등 75)를 쓰지만, 심판은 옛날처럼 한 수(가장 큰 칸 312.5)만 쓴다. 그래서 약한 방향의 넘음은 이 심판이 못 본다.
  - 근력 몫(다친 다리 · 근육 세기)은 안 곱했다. 잣대는 '센 어른' 기준이다.
  - 빠르기는 스텝 앞 값(몸이 토크를 정할 때와 같은 때)을 썼다. 모터 다시 셈은 스텝 뒤 값을 쓴다.
  - 늘어나는 몫의 방향은 견주는 바로 그 벡터로 정했다 (요구는 요구 벡터로 · 잰 값은 잰 벡터로).
  - 패치는 `git diff 08ebf060 -- tools` 로 만들었다. 시키신 `git diff origin/main -- tools` 는 본판에 없는 물리 2.0 도구들(honesty.mjs 를 포함해 36 파일 · 약 5 700 줄)까지 다 들어가서 고친 곳이 안 보인다. 그 꼴도 `judge_vs_main.patch` 로 같이 두었다. 시작 때 확인한 `git diff --stat origin/main HEAD -- src tools` 는 src 만 비고 tools 는 그 36 파일이 달랐다.
