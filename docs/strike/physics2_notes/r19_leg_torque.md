- **A/B (주 방법)**: `probe.mjs` 를 `node --import` 로 얹어 도구를 그대로 돌린다(src · 도구 안 고침). world.step 바로 앞 `takeSnapshot` (명시 토크 · 모터 목표 · 접촉 캐시 다 들어 있음) → 원래 스텝(접촉 걸이 결정을 적어 둠) → 사본(`World.restoreSnapshot`)에서 관절 하나의 모터를 끄고(k = 0 · d = 1e-9) 같고 반대인 토크 쌍 x 를 건다(엉덩이 · 발목 3 축 · 무릎 1 축). 그 싸움꾼 모든 몸의 선 · 각속도(√m · √I 무게)를 원래와 최소제곱으로 맞추는 x 를 찾는다(유한차분 야코비안 · 가우스-뉴턴 4 번). x = 그 스텝에 모터가 낸 평균 토크. 나머지 관절 모터는 그대로.
- 검산 1 — 사본이 원래와 같은가: 사본을 그대로 돌리면 각속도가 **비트까지 같음(det = 0)**. 단 이벤트 줄을 넘겨야 한다(넘기지 않으면 Rapier 가 접촉 걸이를 부르지 않는 길로 가 346 rad/s 까지 달라짐 — 찾아 고침).
- 검산 2 — 알려진 답: 모터 끈 사본에 알려진 토크 X0 를 건 것을 '원래'로 놓고 같은 풀이로 X0 를 되찾음. 5 % 안 + 풀이 잔차(상대 ≤ 0.5 또는 절대 ≤ 0.02) 를 '믿을 표본'으로 씀. 뺀 몫: 엉덩이 · 무릎 · 뜬 발목 0.6 ~ 9 % · **디딘 발목 28 ~ 81 %** (발바닥이 땅에 눌린 스텝은 매끄럽지 않아 x 가 안 갈림). 표는 믿을 표본만 (`*.table.txt`); 뺀 표본을 디딘 쪽은 충격량 읽기 · 뜬 무릎 · 발목은 운동량 정답으로 채운 표가 `*.hyb.txt` (값이 거의 같음 — 뜀 표는 채운 판).
- 검산 3 — 땅 접촉 없는 뜬 다리의 정답(위 Q1 둘째 표): A/B 가 뜬 무릎은 기울기 0.96 ~ 0.97 · 상관 0.999, 뜬 발목은 기울기 1.00 ~ 1.03.
- 함께 본 방법 둘: (i) **충격량 읽기** — 스텝 뒤 스냅숏 바이트에서 JointMotor 의 impulse 칸을 찾음([tv, t, k, d] 네 f32 뒤 +20 바이트). Rapier 는 마지막 작은 스텝(6 개 가운데 하나)의 충격량만 남겨서, 자유 두 몸 시험에서 참값 ÷ (impulse × 6 ÷ dt) = 1.11 ~ 1.14, 게임에서는 디딘 다리엔 A/B 와 기울기 0.84 ~ 1.03 (상관 0.77 ~ 0.98) 이지만 뜬 다리엔 틀림(상관 0.2 ~ 0.35) → 디딘 다리 채움에만 씀. (ii) honesty 의 운동량 셈은 이번에 쓰지 않음(뜬 다리 정답을 같은 식으로 probe 안에서 셈).
- 찾은 덤: Rapier 0.19 에서 `jointConfigureMotor(…, k = 0, d = 0)` 은 모터를 끄지 않고 **그 축을 굳힌다**(토크에 꿈쩍 않음). 게임이 어떤 다리 관절에 k = d = 0 을 넣는 날이 오면 관절이 잠긴다 — 지금 값에서는 안 넣음(감쇠 0 시험은 k > 0).
- 땅 힘: 몸 전체 운동량 잔차(fyM · 도구 fyPeakBW 와 같은 값). 엔진 접촉 충격량 합은 평균 16 % 크게 나와 디딤 판정에만 씀.
