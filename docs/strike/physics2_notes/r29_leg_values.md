## 바뀐 것 (src)

- `legLimit(base, str, wEcc) = base × str × (1 + (LEGS.ecc − 1) × (wEcc ÷ LEGS.eccW 를 0 ~ 1 로 자름))`. `ecc 1` 이면 뒤 괄호가 정확히 1 이라 `base × str` 와 같은 수. `eccW 1` 이면 나눗셈도 같은 수.
- `clampLeg(t, w, lo, hi, str) = clamp(t, −legLimit(lo, str, −w), legLimit(hi, str, w))` — 부모 쪽 + 토크는 w > 0 일 때 늘어나며 버틴다.
- 일곱 자르기(엉덩이 x y z · 무릎 · 발목 x y z)가 이 셈을 지난다. 칸은 오늘과 같다(무릎 − = 폄 · 발목 z + = 발바닥).
- 관절 빠르기: `drive()` 가 골반 각속도를 한 번 읽고(`_wp`), `senseLeg` 가 허벅지 · 정강이 · 발 각속도를 읽어 자식 − 부모를 한도 틀로 놓는다(엉덩이 = 허벅지 틀 · 무릎 = 허벅지 z · 발목 = 발 틀). r27 의 일곱 칸 저장(`av`)은 없앴다 — 받는 값은 같다.
- 할당: 엔진 JS 의 `angvel()` 은 늘 새 `Vector3` 를 돌려주고(몸 값 기억 `src/body_reads.js` 에 있을 때도 새로 만듦), 날 API `rawSet.rbAngvel(h)` 도 새 `RawVector` 를 돌려준다. 미리 잡은 자리에 읽는 꼴이 엔진에 없다. 이 src 의 다른 자리(`trunkRate` · `armMomentum` · `putState`)도 같은 길로 읽는다. 잰 수(10 s 싸움): 싸움꾼 · 스텝마다 다리 몸 angvel 8 번(그 가운데 새 7 · 원래 `trunkRate` 의 골반 1), 엔진까지 간 것 6.99 번. 원래 엔진 읽기였던 골반이 기억 읽기가 되므로 늘어난 엔진 읽기는 6 번 남짓.
