그 값으로 **가까운 찌르기 맞음이 바탕보다 줄었다.** 레이피어 42 → 47 → **26**, 장검 53 → 55 → **53** 이다(/80 · 바탕 → 첫 고침 → 읽기 뒤). 안 본 씨앗에서는 레이피어 52 → 24, 장검 56 → 40 이다.
안 본 씨앗에서 **H1 AI 레이피어 가까운 넘어짐이 FAIL** 이다(6.7 → 14.4 /100 · 옛 위 끝 11.3). 관문 두 묶음에서는 PASS 다.
지금 판은 '몸이 정직한 팔'과 '가까운 찌르기 맞음' 가운데 하나를 고르는 자리다. 여쭘 24 로 올렸다. 아래 1 ~ 5 는 첫 고침 때 쓴 글이다. 줄마다 읽기 뒤 값은 §1 표의 셋째 칸에 있다.

2. **가까운 찌르기는 빨라졌고 맞음은 줄지 않았다.** 탭 → 맞음 가운데값은 레이피어 0.317 → 0.250 s, 장검 0.225 → 0.167 s다. 맞은 획은 레이피어 42 → 47, 장검 53 → 55 (80 번 가운데)다.
   대신 '당김이 끝나야 뻗는다'를 함께 넣었다. 걸음만 옮긴 첫 판은 맞음이 42 → 29 · 53 → 39 로 줄었다(§3 해 본 것).
3. **AI 내려베기 '칼 먼저'는 못 이뤘다 (G1 C1 AI FAIL).** 칼 먼저 몫은 0.262 · 0.214 → 0.267 · 0.212 로 그대로다. 과녁은 0.8 넘게다.

## 2. 왜 사람 길과 AI 길이 달랐나 (베기)

  - (가) 박자 걸음 대신 칼과 그 걸음을 함께 + 두 발 디딘 채에서만 베기: 0.41 (맞은 획 50 → 44)

## 3. 바꾼 것 (함수마다)

- `src/strike_timing.js` (새 파일): `timingOf(f)`는 기본 칸에 유파 칸(`STRIKE_TIMING.school[swordArt.tradition]`)을 덮는다. 그 밖에 `thrustStepAt(f, K)` = K.aim + thrustStep · `strikeStepDelay(f, kind)` = thrustStep | cutStep · `chamberV(f)`.
- `src/config.js`: `STRIKE_TIMING = { base: { thrustStep: 0.04, cutStep: 0.04, chamberV: 0.5 }, school: {} }` (읽기 뒤 chamberV 0.25 · §5).
- `src/skill.js`
  - `thrust()`: 걸음을 곧장 부탁하지 않고 `tap.stepAsk`(꼴 · 길이 그대로)와 `tap.stepAt`에 둔다. stepAt ≤ 0 이면 옛 그대로 곧장 부탁한다.
  - 새 `thrustStepGo()`: 미뤄 둔 걸음을 한 번 부탁한다.
  - `updateThrust()`: (1) 겨눔 끝에 칼자루가 칼 선을 따라 chamberV 넘게 뒤로 가는 중이면 겨눈 채 머문다(많아야 THRUST.extend). (2) 그 뒤 tap.t ≥ stepAt 이면 걸음을 부탁한다. (3) `tp.line` 에 칼 선을 적는다.
- `src/ai.js startStrike()`: `stepDelay` 0.04 → `strikeStepDelay(me, t.kind)`(값 같음). 탭 찌르기면 `thrustStepAt(me, tap.K) / attackSpeed`.
- 해 본 것(넣지 않음): 걸음만 옮긴 판(chamberV 없음)은 L5 0.058 PASS 였지만 가까운 찌르기 맞음이 42 → 29 · 53 → 39 로 줄었다. 레이피어 AI 가까운 넘어짐도 12.9 → 18.5 /100 이라 H1 FAIL 이었다. 까닭은 겨눔 0.11 s 안에 당김 0.3 m(THRUST.driveChamber)가 끝나지 않아 덜 당긴 팔로 뻗은 것이다(`$S/r23/vA/`).
