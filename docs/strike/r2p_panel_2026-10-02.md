## 2. 설계별 치명 실패 모드 (심사가 증거를 든 것)
### A
- **(①·② 공통) 엉덩이 y 축 명시 토크 쌍(k 3600·d 320·sat 560)의 수치 발산.** 허벅지(캡슐 7.5 kg·r 0.065) 비틀기 관성 ≈ 0.016, 정강이·발 포함 ≈ 0.02~0.035 kg·m². 심플렉틱 오일러 명시 PD 안정 조건 d < 2I/dt·k < 4I/dt² (dt 1/120) → d < 4.8~8, k < 1150~2000. fighter.js:2152 주석("위팔 비틀림 관성 ≈0.003 → 강도 ≤10·감쇠 ≤0.2")이 같은 이유로 이미 비틀기 이득을 묶고 있다. 560 포화를 한 스텝 명시로 주면 Δω ≈ 133~230 rad/s. R10 의 "두 다리 나눔"은 각 다리 이득을 줄이지 않아 치료가 아니다.
- **(②) 비틀기 토크의 싱크가 작다.** 반작용은 허벅지 → 무릎 경첩(비틀기 잠김) → 정강이 → 발목 공 관절(y ±0.3) → 발 yaw 핀(gait.js:1013-1024, 한계 μ·N_f·0.05 ≈ 13 N·m/발)으로만 간다. "땅 ≈ 180 N·m" 는 골반 회전이 엉덩이를 끌어 다리가 기울 때의 **구속 반력**(수평 마찰 힘쌍)이지 비틀기 토크의 반작용 길이 아니다 → 발목 17° 한계에 부딪히고 발이 yaw 미끄러지며 골반은 13~27 N·m 몫만 받을 수 있다(G2 잔차 0 에 가까워도 G6 무거운 힘은 C2 아래 = F1+O1 의 5.28 모양).
- (①) 'asis' 560 비틀기 상한은 자기 표(사람 60~100)의 5~9 배인데 "발 마찰이 먼저 막는다"로 덮는다; 골반 pitch·roll 닻·±240 N 밀기·감쇠항 상한 밖은 남는다.

### B
- **(①) 계획기가 손가락 박자를 지운다.** §2.4 "e > s_stop·margin 이면 ω_t = ω + α_acc·dt" — ω = 0 이면 s_stop = 0 이라 어떤 작은 e 에도 전속 가속 → 한두 스텝 뒤 제동 전환 → 작은 오차 둘레에서 상한 토크 떨림(bind·느린 압박·속임 불가). §5 가 스스로 "손가락이 느리게 그어도 팔은 예산 최대로 민다"고 적었다 — hair-trigger(손가락=손)·사장님 "일촉즉발"(빠르기 선택권은 사람 몫)과 정면 충돌. 막으려면 사각지대·margin 문턱이 또 들어간다. 덤: σ 축소는 d·ω 가 클 때 k 까지 떨어뜨려 빠른 동작 중 자세 강성이 무너진다.
- **(②) 연체동물이 다리에서 재발한다.** ζ 0.8, d = 2ζ√(k·I_eff) 에서 I_eff 를 "관절 아래 자식 사슬"로 정의했는데 딛은 다리의 무릎·엉덩이가 실제로 움직이는 질량은 위의 몸 전체(뒤집힌 진자, ≈ 60 kg·m²)다 → 무릎 d 100 → ≈16 으로 저감쇠, 동시에 무릎 500→210·엉덩이 560→208 + 받침 0.2 유지 조합은 support_optimum a0.1 선례(무릎 한도 닿음·밀림 회복 2배)와 10/1 'human' 기각 조건을 다시 밟는다. 올릴 수 있는 수가 전부 사장님 몫이라 현장 손잡이가 없다.
- (①·②) 123·124 행은 사장님 10/1 18:40 결론(legTorque 'asis', 'human' 손맛 바닥 ✗ — 걷기 무릎 한도 닿음 0.42–0.62·밀치기 미발사 13/40, config.js:64)을 더 센 형태로 뒤집는다. s0.5 '상한 둔 닻 yaw'는 자기 원칙(약한 닻 = 보이지 않는 힘) 위반 후보. W2 1.5 일에 driveJoints·manualMuscle·elbowGravity 전면 재작성 + 계획기 + 장부 + 'off' 바이트 동일은 경험상 4~6 일; 'off' 바이트 동일은 재작성 설계가 가장 쉽게 깬다.

### C
- **(①) S1 이 관문을 오염시킨다.** §2.3 "push() 의 수직 몫을 딛은 발 발바닥 점에 addForceAtPoint(−fy·w_k)" — 발을 땅에 누르면 Rapier 접촉 임펄스(gait.js groundForce 1061-1067)가 fy 만큼 커지고 그 N 이 pinFeet 마찰 한계 μ·Nf(980-981)·wF·발 하중 p10·'마찰 예산 μ·min(N)·d'(§2.6·§6)에 그대로 들어간다. 보이지 않는 147 N(+스프링 몫)이 '발이 받치는 몸무게'로 둔갑해 S2 관문 "서기 p10 ≥ 0.9"와 A 의 땅 돌림힘 상한이 20 % 부풀려진 채 통과한다. §2.2 잔차식은 S1 뒤 fy 를 두 번 센다. "장부 닫힘"은 측정이 아니라 정의로 통과한다.
- **(②) 132 padOver 가 죽어 있다.** skill.js:555-557 `if (off.length() > R) off.setLength(R)` 는 handOffset 자체를 제자리에서 자른다 → 넘침은 누적되지 않고 한 프레임 Δ(폰 1~3 cm)만 남아 padOver ≈ 0.02~0.05, 걸음 추가 ≈ 1 cm. "자르기는 그대로"라고 못 박았으므로 문서대로 구현하면 §5 ①·R4 가 모두 무의미. S2-a 체중 이동은 무게중심 오차 → 엉덩이 IK 목표 → 핀 발(20000 N/m) 되먹임 고리라 직렬 스프링 떨림(R2 자인)이 거의 확실하고 그 되돌림(k_shift 0.5·2차 필터)은 새 시계값이 된다.
- (①) padOver→걸음·aS·S→체중은 손가락 크기→이동 채널이라 H1-A 재발 경로(R4 자인). O1 은 손대지 않는다. 첫 탐색판(S1)은 "눈에 거의 같아야" 하는 것이라 사장님 세 물음에 답을 못 주고 손맛은 4~5 일째.

## 4. 차단 조건 (두 심사의 합집합, 명세가 지킨 것)
1. **약한 닻·상한 둔 닻 yaw 금지** — 질량 무한 몸체의 토크는 크기와 무관하게 반작용이 땅으로 안 간다. 닻 yaw 는 0 아니면 오늘 그대로. (→ §2.2 K1)
2. **다리·발목·허벅지 비틀기 축에 명시 addTorque PD 금지** — 120 Hz 에서 I ≈ 0.02 → d < 4.8·k < 1150. 명시로 가려면 매 스텝 I_eff 로 안정 조건을 확인하는 식을 먼저 문서에. (→ 암시 σ 로만)
3. **B 계획기(bang-bang ω_t)는 어느 탐색판에도 넣지 않는다** — 사장님이 '손가락이 느려도 팔은 최고속'을 명시적으로 받기 전엔. (→ 미반영)
4. **B 123·124(다리·척추 상한 사람 값 전면 교체)는 기본값·탐색판 기본에 못 들어간다** — 10/1 결론 뒤집기. 기존 `BODY.legTorque 'human'` 칸으로만 비교. (→ 124·W3)
5. **C S1 금지** — 보이지 않는 fy 를 발바닥 점에 싣지 않는다. 받침은 선언한 외부 힘으로 장부에 남기고 N 에서 분리해 잰다. (→ §2.1)
6. **손가락 크기 → 이동 채널**(C 132 padOver, 128 aS·S, 패드 감도 상향)은 어느 탐색판에도 기본 켬 없음 — H1-A 재발 경로. (→ 미반영·사장님)
7. **첫 탐색판의 새 수 ≤ 3**(스위치 1 + ζ 1 + lunge 끔 1). (→ §3: 122·125·126, 새 수는 125 하나)
8. **확인표 번호**: 세 문서가 122~ 를 각자 썼고 모르겐슈테른이 130~150 을 쓴다 → 종합 담당 배정: R2′ 122~129 + 151~156, 130~150 비움. (→ owner_defaults_table (카))
9. **바이트 동일 관문은 도구로**: 새 줄은 스위치 분기 안 함수 입구 한 곳, corr_s0 꼴 스텝 다이제스트 cmp 를 완료 조건에. 'off' 경로는 옛 함수 그대로. (→ §5 G1·§6 W1b)
10. **정의로 통과하는 관문을 성과로 세지 않는다**(C '장부 닫힘', B '어긋날 수 없다'). 관문은 잔차·발 하중·넘어짐·칼끝 m/s 처럼 설계 밖에서 재는 수만. (→ §5 머리말)
11. **'땅이 ≈180 N·m 를 받친다'는 W1 측정 전엔 관문 숫자에 쓰지 않는다.** (→ §2.1 어림 표기, G2b)
12. 척추 ζ 를 낮추다 ±45° 덜컥이 나면 ζ 를 되돌리지 '쿠션·소프트 한도'를 넣지 않는다. (→ R4)
13. 상자 밖 값(catchMode 'step', assist 0·'fall', 손 필터 끄기)은 탐색판 URL 인자로만, 본판 기본값 변경 0. main push 는 디렉터·사장님 판정 뒤. (→ §2.5)
14. 설계 문서 셋이 untracked 였다 → 심사 반영 전에 r2p-design 에 함께 커밋해 번호·버전 기준(e028f42)을 고정. (→ 이 커밋)
15. 모델 이름 표기 금지: 세 문서·이 문서·명세·커밋 메시지 본문·탐색판 HUD 모두 1·2·3 등급만.
