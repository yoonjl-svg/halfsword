# 일어서기 다리 차례 — "두 다리로 동시에 일어나는 모습" 조사와 시제품 (2026-10-08, 디렉터)

- 사장님 10/8 17:50: "넘어졌을 때 다시 일어서면서 종종 두 다리로 동시에 일어나는 듯한 모습이 나와. 명백한 잘못이니 개선 방안을 찾아봐. 샛별 말로는 두 다리가 동시에 작동하도록 만드는 움직임 코드가 있었다는데 고치지는 못한 모양."
- 결론 먼저: **원인 코드는 하나의 비율 `kneelAmount` 가 두 다리의 관절 목표를 함께 섞는 자리(fighter.js applyPose 의 무릎 꿇기 자세 K)** 다. 일어서는 0.9 s 동안 앞·뒤 무릎이 같은 속도로 펴지고(절반 펴진 때 차 0.03~0.07 s), 몸은 보이지 않는 골반 받침이 일정한 빠르기로 올린다 → 승강기처럼 두 다리가 함께 펴지는 모습. 시제품 `BODY.getupLead`(기본 0 = 오늘, `?getupLead=1`) 는 앞다리(딛은 다리 F)가 먼저 펴고 뒷다리 B 는 riseTime 의 `getupLag`(0.4) 몫만큼 접힌 채 기다렸다가 뒤따라 편다 — 뒷발이 3~20 cm 떠서 뒤따라 딛는 걸음 꼴. 선 때·다시 넘어짐·받침 힘 길은 그대로.

## 1. 오늘의 일어서기 (측정, `tools/sim/getup_probe.mjs`)

상태기계(fighter.js updateState): stand → (가벼운 넘어짐: 발 디딤 잃음·균형 0) → **getup** [무릎 kneelTime 1.1 s → 일어서기 riseTime 0.9 s] → stand. 완전히 쓰러지면 down(fallDuration 2.2 s) 을 거쳐 같은 getup 으로. 밀기 300 N·s(support_measure getup 장면과 같은 꼴) 는 늘 가벼운 넘어짐이다(800 N·s 도).

| 구간 | 무엇이 일어나나 (씨앗 40, 밀기 300 N·s) |
|---|---|
| 무릎 단계 0~1.1 s | 근육 1 → 0.5 로 풀리고 받침 스프링은 골반이 목표 높이(0.95 − 0.43 = 0.52 m)보다 0.25 m 위면 0 → 몸이 **0.84 → 0.25 m 까지 주저앉았다가** 받침(최고 1.28 Mg)이 0.645 m 까지 다시 들어 올린다. 두 발은 바닥에 평평(발바닥 0.09/0.11 m), **무릎·손은 땅에 닿지 않는다**(정강이·손 반력 0) — 설계의 "뒷무릎을 땅에" 는 실제로는 두 발 쪼그려 앉기다 |
| 일어서기 1.1~2.0 s | `kneelAmount` 1 → 0 선형. 앞 무릎 −82° → −10°, 뒷 무릎 −99° → −4° 가 **같은 걸음으로** 펴진다(절반 펴진 때 F 1.73 s · B 1.80 s). 골반 0.645 → 0.97 m 일정 속도, 보이지 않는 받침 fy 0.5 → 0.87 Mg, 발 반력 앞 0.1 → 0 · 뒤 0.5~0.6 Mg |
| 선 뒤 0~0.6 s | gait.enter: 두 발을 그 자리에 딛고 levH 1 → 받침 ≈ 1.0 Mg, 발 반력 ≈ 0; 0.6 s 뒤 넘겨받기와 고쳐 딛기 걸음 |

관련 코드(샛별이 말한 "두 다리를 동시에 움직이는 코드" 로 보이는 것 셋):
1. `fighter.js applyPose` — `const kn = this.kneelAmount; K('thighF', 1.25) … K('footB', 0.8)` 여섯 관절을 **같은 kn** 으로 slerp. ← 모습의 원인.
2. `fighter.js driveBalance` — 무릎 꿇기 중 `load.F = max(load.F, 0.6); load.B = max(load.B, 0.6)` 두 발 하중 바닥을 똑같이. (footReaction 0 이라 힘에는 영향 없음, legPower·grip 에만)
3. `gait.js enter()` — 선 순간 두 발을 동시에 그 자리에 딛음(stance true ×2) 뒤 고쳐 딛기. (선 뒤의 일, 이번 모습과는 다른 자리)

## 2. 시제품 `BODY.getupLead` (기본 0 — 끄면 바이트 동일)

- `kneelAmountB` getter: 일어서기 구간 u = (t − kneelTime)/riseTime 에서 뒷다리 몫 = clamp(1 − (u − lag)/(1 − lag)). 앞다리는 오늘 그대로 `kneelAmount`. applyPose 의 K 가 F 관절엔 kn, B 관절엔 knB 를 쓴다. 받침 높이(crouch)·근육·시간표·넘어짐 판정·받침 힘은 손대지 않았다. `?getupLead=1 ?getupLag=0.4`.
- 뒷다리가 접힌 채 기다리는 동안 골반이 오르므로 뒷발이 저절로 떠서(걸음처럼) 남은 시간에 펴져 뒤에 딛는다. 사람이 한쪽 무릎에서 일어설 때 앞발로 밀어 서고 뒷발이 뒤따르는 차례.

| 조건 (12 씨앗, 밀기 300 ± 15 %·방향 ± 0.3 rad) | 선 때 (밀기 뒤 s) | 다시 넘어짐 | 무릎 절반 펴진 때 차 B − F (s) | 서는 동안 뒷발 최고 높이 (m) | 앞발 반력 (서는 동안) |
|---|---|---|---|---|---|
| 오늘 (getupLead 0) | 2.18~2.21 | 0/12 | 0.03~0.07 | 0.02~0.07 | 0.1 → 0 Mg (뒷발 0.5~0.6) |
| getupLead 1 · lag 0.4 | 2.18~2.21 (같음) | 0/12 | **0.13~0.23** | **0.03~0.20** | **0.3~0.47 Mg, 뒷발 0 (약 0.5 s)** |
| 완전히 쓰러짐(down) 뒤 · 3 씨앗 | 4.22 둘 다 | 0/3 | 0 → 0.17 | 0.23 → 0.36 | – |

lag 쓸기(씨앗 40): 0.3 → 차 0.17 s·뒷발 0.015 m / **0.4 → 0.20·0.071** / 0.5 → 0.23·0.163 / 0.6 → 0.27·0.278. 값이 클수록 뒷발을 높이 들고 늦게 딛는다(걸음이 또렷). 선 때는 모두 같다(시간표가 상태를 정하므로).

눈 확인(브라우저 옆 카메라, 상대를 가볍게 넘어뜨리고 1.27~1.86 s 여섯 장면, `docs/handoff/getup_lead_2026-10-08.jpg`): 끔 = 두 발을 땅에 둔 채 두 다리가 함께 펴짐(런지에서 두 다리로 밀어 서는 꼴). 켬 0.4 = 앞다리로 서며 1.4~1.7 s 뒷발이 떠서 뒤따라 딛음. 켬 0.6 = 뒷발을 더 높이(0.35 m)·늦게(1.86 s 에 내려옴) — 걸음이 또렷하되 조금 과장돼 보일 수 있다(사장님 눈).
