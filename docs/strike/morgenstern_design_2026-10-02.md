## 2. 물리
### 2-1. 이 게임의 무기 몸체 모델 (fighter.js 읽은 것)
- `spec.buildParts(look)` → 부품마다 `[모양, y, [질량, 부품 안 무게중심 y, 휘두름 관성 Ie, 축 관성 It], 색, 칼날?]`(`weapons.js partTuple`). `fighter.js:549~` 가 부품마다 콜라이더를 만들고 `setMassProperties(m, com, {x:Ie, y:It, z:Ie})` — **관성은 우리가 준 값**, 콜라이더 모양은 접촉에만 쓴다. 공 모양은 `['ball', r]`(폼멜과 같은 길).
- 칼 몸체는 아래팔 앞끝에 **공 관절**(`gripJoint`, `fighter.js:617`)로 붙는다. 손목 = 이 관절. 타격 계산용으로 `swordProps{m, I(주축), frame}`, `swordIhand = max(Ix,Iz) + m·lc²`(손 기준 휘두름 관성), `swordCom`, `twistScale = pI.y / TWIST_I_BASE(0.0010137)`(`fighter.js:31·632`).
- `bladeLength` 는 **'blade' 부품 구간의 길이**: `bladePoint(t)` = 손 + (hiltLength + t·bladeLength) 축 방향(`fighter.js:673`), `combat.analyze` 의 `t = (local.y − HL)/bladeLength`(`combat.js:150`) 로 찌르기 창(t > 0.8)을 가른다. 즉 **머리를 'blade' 부품으로 두면 hiltLength = 머리 밑, bladeLength = 머리 길이**가 된다 — 나뭇가지·참치와 같은 방식(둘 다 몸통 상자가 'blade' 부품, `isBlade` 플래그는 false).

### 2-2. 철구의 표현 (부품 세 벌)
```
// weapons.js (후보 M-B — 값은 확인표 130~132)
hiltLength: 0.54, bladeLength: 0.14, gripAlong: -0.14,
buildParts(look) {
  const haft = boxInertia(0.60, 0.016, 0.335, 0.016);        // 자루 y −0.13 ~ 0.54 (한 상자)
  const cap  = sphereInertia(0.08, 0.02);                      // 밑마개 y −0.135
  const head = sphereInertia(1.20, 0.035);                     // 연철 공 (가시는 질량 안에 포함)
  return [
    partTuple(['box', 0.016, 0.335, 0.016], 0.205, 0.60, 0, haft.Ie, haft.It, null),
    partTuple(['ball', 0.02], -0.135, 0.08, 0, cap.Ie, cap.It, null),
    partTuple(['ball', 0.05], 0.61, 1.20, 0, head.Ie, head.It, null, true), // 'blade' 부품 = 머리. isBlade 참 → 'blade' part, FILTER_CONTACT_PAIRS
  ];
},
```
- **끝에 몰린 질량·관성**: 손 기준 I 0.50 의 **89 %** 가 머리의 m·r²(1.2 × 0.61² = 0.447). 공 자체의 0.4·m·r² 는 0.0006 — 모양은 거의 안 중요하고 **어디에 두느냐**만 중요하다.
- **비틀림 축**: 모든 부품이 축 위라 pI.y = ΣIt ≈ 0.0001(자루) + 0.00001(마개) + 0.0006(공) ≈ **0.0007 → twistScale ≈ 0.69**(자동). 롱소드(1.0)와 같은 자리수라 날 세우기 서보가 안정 범위 — `controlOverrides.twistScale` 없이 둔다. `docs/weapon_motions.md` §5-2 규칙 4 "날 세우기를 끄지 마라"(참치 23 → 8 %) 를 따른다. 날이 없어 날 세우기는 겉으로 안 보인다.
- **충돌 모양**: 공 r 0.05(몸체 Ø 6.5 cm 는 1.5 cm 안, 가시 끝 Ø 13 cm 는 1.5 cm 밖) — 나뭇가지의 잔가지(6~7 cm 밖)보다 약속(~1 cm)에 가깝다. 가시 끝 1.5 cm 가 보이는데 안 닿는 것은 '가시 사이로 미끄러진다' 로 읽힌다. 접촉 `part` 는 머리 = 'blade', 자루·마개 = 'hilt'(늘 둔기).
- `isBlade` 를 참으로 두는 까닭: `colliderInfo.part='blade'` 가 되어 `filterContactPair` 훅(가르기 예측)과 `analyze` 의 `t` 가 머리에서 돈다. 날 없음(`weaponCfg.edged` 거짓)이라 예측은 늘 "가르지 못함 → 1(부딪힘)" 이고 상처는 접촉힘 사건(`rebound` 길)에서 난다 — 참치·나뭇가지와 같다. `bladeMesh` 는 머리 메쉬(피가 공에 묻는다).

### 2-3. 칼 구동(driveSword)이 무거운 머리를 다루는 법
- 토크 상한 `cap = maxAimTorque(22) × str × hill(손목 각속도, wristVmax 30·√str)`(`fighter.js:2332·2363`). 중력 토크도 **같은 상한 안**에서 버틴다(`gravityTorque … torque.add(_mG)`, 2355~2357): M-B 를 수평으로 들면 1.88 × 9.81 × 0.45 = **8.3 N·m**(롱소드 3.8) → 남는 힘 13.7 N·m, 각가속도 **27 rad/s²**(롱소드 67). 머리 위 자세에선 중력 몫이 줄어 44 rad/s².
- 놓아주기·제동: `brakeAcc = cap·brakeEcc / swordIhand` 라 I 가 1.85배면 멈출 거리(`stopAngle`)도 1.85배 → **일찍 제동을 시작**해 가시 끝 속도가 더 낮다. 측정(8절): 둔타 E 중앙값 14~23 J → 가시 끝 3.3~4.2 m/s, 최대 132 J → 10 m/s(롱소드 칼끝 18~21 m/s).
- 그래도 **한 번 닿으면 무겁다**: 머리의 자유 유효질량 ≈ 1.0 kg(롱소드 끝 0.18) → `rebound` 의 `gripMass`(+손 1.5 kg) 가 커서 판·투구에 되튈 때 충격량 J = mB·vPre + ΔJ 가 10 N·s 를 넘는다 → `takeJolt`(RECOIL.joltImpulse 3) 매번 '크게 부딪힘', `absorbWeaponImpact(J)` 는 `min(1, J/6)²` 가 1 에 붙어 **파손 굴림이 매번 fragility 그대로**(0.032) 돈다.
- 손목·팔 한도(`BODY.humanLimits`): 손목 원뿔(아래팔-무기 각 ≤ 163°)·아래팔 돌림 ±80°·어깨 들림 면은 **밧줄**이라 머리 무게가 늘어나도 한도 자체는 같다. 다만 정적 처짐: 세이버 표의 '긴 자세'(손 0.68 m 앞, 칼끝 수평)에서 8.3 N·m 를 22 중 늘 쓰고 있어 머리가 처진다 — Q1 "대가는 물리로" 그대로. 토크 28(츠바이핸더 선례)은 **줄 137** 대안.
- `techReachScale`·간격: `ai.js MEASURED` 에 줄이 없으면 길이 비(0.68/1.18 = 0.58)로 간격을 줄여 **너무 가깝게 선다**(proto_weapons 가 세이버 줄 × (0.6+0.4r) 로 땜질한 까닭). 로스터에 넣을 때 `node tools/sim/weapon_measure.mjs morgenstern` 으로 실측 줄을 넣는다(줄 144).

### 2-4. 가시 = 약한 찌르기 (`spike`, combat.js 한 줄)
- 지금 `isBlade = part==='blade' && local.y > HL−0.01 && weaponCfg.edged && …`(`combat.js:152`) 라 날 없는 무기는 베기도 찌르기도 없다. 가시는 **찌르기만** 열면 된다:
```
// combat.js analyze (제안): spike 무기는 머리 끝(t > 0.8)으로 칼 축을 따라 들어갈 때만 찌르기. 베기는 없다. 확인표 135
const spike = !isBlade && pr.w.part === 'blade' && att.weaponCfg.spike && !att.weaponBroken;
if (isBlade) { …기존… } else if (spike && along > STRIKE.stabAlign && t > 0.8) type = 'stab';
```
- 문턱은 기존 식 그대로: `thr = A.stab × guard`(살 20~25 J × 옷 0.55~1). **판금·투구 위에서는 둔기 그대로** — 두 가지 길 중 하나: (a) `plateGuard > 0 || helmOn` 이면 `type='blunt'` 로 되돌림(조건 한 줄), (b) 기존 식에 맡기면 판 문턱 47 × guard ÷ mThrust 0.35 = **134 J** 넘는 찌르기만 판을 뚫는데 모르겐슈테른 찌르기는 플레이어 탭(thrustAssist 3.5 kg)으로도 30~60 J 라 사실상 안 뚫린다. **(b) 추천** — 조건이 하나도 안 는다(줄 135 메모).
- `mThrust 0.35`(줄 135): 세이버 0.7 의 절반. 가시 한 개가 받는 단면이 작아 꽂히지만 깊이가 3 cm 뿐 → 심각도 `(eff−thr)/60` 작게, 출혈 작게. `mCut` 은 안 읽힌다(베기 길 없음) — 0 으로 적어 둔다.
- 찌르기 즉사(finish): `finish = type==='stab' && tap.down && … && vic.state==='down' && FINISH_PARTS`(`combat.js:166`) 는 **type 만 본다** → 가시로 누운 상대 몸통·머리를 축 방향으로 찍으면 즉사. 조건을 더하지 않는 기본값은 이것(가시 = 찌르기), 대안은 `!spike` 한 조건(둔기 찍기 = 기절) — **줄 142** 로 여쭘(6절).
- 분류: `classifyStyle` 은 `edged === false` 면 바로 `'blunt'` → `spike` 와 무관하게 ④ 때리기 유지. 무기 층 `families` 도 찌르기 없음 그대로(AI 는 가시로 찌르는 기술을 고르지 않는다 — 플레이어 탭만).

### 2-5. 파손 — 나무 자루가 부러지고 머리가 떨어진다
- [기존] `BREAK`: 확률 `fragility × min(1, J/6)²`, 레어 표 0.032, 부러지는 자리 `breakAt`(칼날 비율 0.05~0.95, `fighter.breakWeapon:1611`) → 지금 식으로는 **머리 안**에서만 끊긴다(cutY = HL + at·bladeLength). 쇠 공이 반으로 갈라질 리 없다.
- **제안(줄 139)**: 스펙 `breakY: 0.40`(손 기준 절대 높이, 자루 위쪽 보강띠 밑) 을 `breakWeapon` 이 `breakAt` 대신 읽는다 — `trimSword(cutY)` 는 이미 "절단선 위에 통째로 있는 부품은 `setEnabled(false)`"(`fighter.js:1636`, 주석 "지금 무기엔 없다") 길이 있어 머리 콜라이더가 꺼지고 자루 상자가 잘린다. 겉모습 `breakWeaponLook(group, cutY)` 도 절단선 위 메쉬를 통째로 조각으로 넘긴다(`weapon_looks.js:1266~`) → **머리가 날아간다**(debris.js). 남는 것: 자루 0.4 m 토막 ≈ 0.36 kg(+마개) 의 둔기. `cfg.hiltLength/bladeLength` 는 남은 자루에 맞춰 `hiltLength = breakY − 0.02, bladeLength = 0.02` 로 두면 `bladePoint`·`finish`·AI 간격이 토막 길이를 읽는다(구현 담당이 `trimSword` 뒤 값 둘 갱신 — Q14 "파손은 물리대로" 안).
- 기본 fragility 는 레어 표 0.032 그대로(Q14 "파손표를 다시 맞추지 않는다"). 단 2-3 에서 본 대로 J 가 늘 6 N·s 를 넘어 **매 되튐마다 3.2 %** — 60초 경합(`weapon_break_rate.mjs`) 에서 레어 목표(9 % → 2배 18 %)보다 높게 나올 수 있다. 그때 `fragility` 를 무기 줄로 낮추는 것은 **등급표를 바꾸는 것이 아니라 무기 스펙 값**이지만 사장님 확인 줄(139)로 간다. `breakY` 가 v1 에 못 들어가면 임시로 `fragility: 0`(참치 선례 "안 부서진다") — 이것도 줄 139 의 대안.

## 6. AI
- **자세표**: `oneHandStance`(한손 기본) → `guardBaseOne('blunt')` = **ONE_HAND_SABRE** 표(`guards.js:60~`): 감는 자세는 팔꿈치 굽혀 어깨·머리 옆, 긴 자세는 손 0.68 m 앞. 세이버·팔쉬온·나뭇가지와 같은 표 — 바꿀 것 없음.
- **무기 층**(`weapon_class.js WEAPON_LAYER`, 게임은 아직 안 읽음): style 'blunt' → families 네 베기 무리만(찌르기 없음), T0 = 0.24 × √((0.50+0.547)/(0.179+0.547)) = **0.29 s**(세이버 0.24·롱소드 0.30), WIND/FOLLOW 0.85(한손), TRUNK 0.25. R2′ 가 이 값을 읽기 시작하면 '머리 무거운 한손' 은 세이버보다 20 % 느린 베기 위상으로 나온다.
- **유파**: `schools.js` 에 모르겐슈테른 줄이 없으면 AI 가 쥘 때 `longsword` 유파(간격은 `MEASURED` 줄)로 싸운다. 제안(캐릭터 PM 몫, 값만): `tree_branch` 유파처럼 **찌르기 기술 없는 7기술**(C④ "AI 는 찌르기 기술을 쓰지 않는다", `docs/weapon_types.md` §4-3) + 세이버 `measure`. 가시 찌르기 기술을 AI 에 줄지는 **줄 143** — 플레이어 탭(thrustAssist 3.5 kg)과 달리 AI 찌르기는 `thrustStyle` 없는 무기에서 `skill.thrust` 를 안 불러(`ai.js:928`) 손 길만 가므로 30 J 도 못 낸다 → 기본은 없음.
- **AI 가 모르겐슈테른을 드는 때**: 캐릭터 시트는 저마다 무기가 정해져 있어 본판에서 AI 가 드는 일은 `?foeWeapon=morgenstern`·시뮬뿐. 카드는 플레이어용. 어느 캐릭터가 둔기를 들지는 캐릭터 PM 에 여쭘(줄 148 메모).
- **마무리(finisher)**: `finish.js:135 blunt = !edged || weaponBroken` → 누운 상대의 **머리**를 겨눠 내려찍는다(몸통 둔타는 멍뿐이라). 결과는 `applyWound` 머리 둔기 규칙: 의식 −E/140(맨머리) → 100~300 J 찍기 한두 번이면 의식 0 → `die('기절')`. **즉사 규칙(`finish`)은 찌르기만**이라 둔기 찍기는 기절로 끝난다 — 지금 규칙 그대로 둘지 **사장님께 여쭘(줄 142)**. 2-4 의 가시 때문에 축 방향으로 찍으면 'stab' 이 되어 즉사가 걸린다: 기본값 = 가시도 찌르기(조건 없음), 대안 = `finish && !spike`.
- **판금 상대 마무리**: `neck = !blunt && torsoPlated` 라 둔기는 목으로 안 옮기고 머리를 찍는다 → 투구 위면 `helmetBlunt`(케틀햇 0.4, 뿔 0.5) 로 줄고 200 J 넘으면 투구가 벗겨진 뒤 다음 찍기가 맨머리 — 사장님 10/1 "확률 아닌 물리" 와 같은 결.

## 9. 위험
1. **지금 모델에서 약하다** — 팔 힘 22 N·m 로 I 0.5 를 돌리면 가시 끝 3~10 m/s. 온몸 타격(R2′·R3)·Q13 1-1 전에는 롱소드 상대 0~10 % 로 사장님 기준 1(0 % 없음)을 못 지킬 수 있다. 완화: 카드에 나오되 `docs` 에 '측정 전' 표시, R3 뒤 재측정. 토크 28·mBlunt 로 억지로 올리지 않는다(사장님 "온몸 타격이 들어와야 선다", 줄 134·137 로만).
2. **가시 즉사**: `spike` 로 'stab' 이 열리면 쓰러진 상대 몸통 찍기가 즉사 — 사장님이 "둔기 찍기는 기절" 을 원하시면 조건 하나(`!spike`)가 든다(줄 142).
3. **파손 길의 새 코드**: `breakY` 는 `trimSword` 의 '통째로 떨어지는 부품' 가지를 처음 쓴다(주석 "지금 무기엔 없다") — 머리 콜라이더 끔 뒤 `swordProps`·`twistScale` 재계산, `bladeMesh` 가 떨어진 뒤 `bloodyBlade` 가 없는 메쉬를 만지지 않게 확인. 못 하면 임시 `fragility 0`(줄 139).
4. **잔상·소리 포화**: 잔상은 한 줄(`trailFor`), 소리 `blunt()` 포화는 소리 담당 몫.
5. **카드 확률**: 레어 2종이 되어 츠바이핸더 노출이 반으로 — 알려 드림(줄 147).
6. **AI 간격**: `MEASURED` 줄 없이 올리면 AI 가 0.93 m 까지 붙어 서서 롱소드에 맞기만 한다 — 로스터 커밋에 실측 줄을 같이 넣는다(줄 144).
7. **불변 관문**: 모든 변경이 `weaponCfg.spike`·`edged === false`·무기 id 로만 갈라지는지 — fights12/live_battery sha 가 관문.

### 11-1. 설계와 다르게 한 것
1. **`fighter.js` 한 줄 더**: `partMesh: hiddenParts` 인 'blade' 부품(철구)은 메쉬에 재질이 없어 생성자 597행 `mesh.material.color` 에서 죽었다 → `mesh.material?.color.clone() ?? null`(재질 있는 무기는 같은 값), 밑색은 decorate 의 `group.userData.bladeMesh` 가 준다.
2. **`trimSword` 공 부품 가지**: '통째로 떨어지는 부품' 가지는 상자 부품만 보고 공은 `return` 했다 → 공도 `y − r ≥ cutY − 0.005` 면 콜라이더를 끈다(폼멜·컵 힐트는 늘 절단선 아래라 예전과 같음). 파손 뒤 질량 1.88 → 0.555 kg, I(손) 0.496 → 0.021, twistScale 0.69 → 0.09, hilt/blade 0.38/0.02, 머리·가시·목 띠 메쉬는 조각으로(`docs/weapon_shots/break_morgenstern_0~3.jpg`), 10 s NaN 0.
