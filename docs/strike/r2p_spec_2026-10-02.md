## 0. 다섯 줄 요약
1. 지금 골반 yaw 를 돌리는 유일한 구동기는 **질량 무한 운동학 닻**(fighter.js:483-492·1813-1836: 2500 N·m/rad·330, 상한 없음, 반작용 없음)이다. 다리는 골반을 돌리지 않는다 — legIK(gait.js:895-923)가 **실제** 골반 자세에서 허벅지 목표를 풀어 엉덩이 비틀기 오차가 늘 0 이다. "다리 → 척추 → 팔" 순서가 물리적으로 나올 수 없는 뿌리이고, R2 진단 O1·H1-B 의 본판 뿌리다.
2. 명세: 닻의 yaw 권한을 **0** 으로 하고(약한 닻·상한 둔 닻 없음, 0 아니면 오늘 그대로 둘뿐), 골반 yaw 목표를 **딛은 다리의 엉덩이 비틀기 근육**에 준다. 구동기는 명시 토크가 아니라 **엔진 암시 모터 + 포화 축소 σ**(감쇠항까지 기존 상한 j.max×mus 안, 속도 목표 0)다 — 허벅지 비틀기 관성(≈0.02 kg·m²)에서 명시 PD 는 발산한다(심사 1·2 공통). 반작용은 허벅지 → 정강이 → 발 → 발바닥 핀·접촉 마찰로 땅에 간다. **땅이 받칠 수 있는 만큼만 몸이 돌고, 그 이상은 발이 미끄러진다.**
3. 척추는 목표 식 그대로, 비틀기 축만 감쇠항 속도 목표 0(수동 감쇠) + 감쇠비 ζ 사람 띠(오늘 1.4 → 0.5 후보, 첫 탐색판의 **유일한 새 수**). 팔·손목·칼·보정 v2·사람 관절 한도·받침 0.2·catch 는 그대로(사장님 10/1 결정 불변).
4. 손가락은 끝점·칼끝 방향·넘침각(얼마나 감았나)만 주고 빠르기는 주지 않는다. 분류기·클립·계획기 없음 → 오독이 정의상 없고, "손가락이 느려도 팔은 최고속"(B 계획기)은 넣지 않는다 — hair-trigger(손가락=손) 유지.
5. 측정은 장부가 아니라 **보존 잔차** r_z = dL_z/dt − τ_땅 이다. 오늘 그 잔차가 곧 닻 yaw 토크다. 여기에 B 의 '포화율·숨은 일률', C 의 '마찰 예산·발 하중·wF' 열을 접붙여 `tools/sim/chain_ledger.mjs` 하나로 잰다. 첫 탐색판(`?chain=legs`)은 **48 시간 안**(W1).

## 2. 기구 — 단계: 발 지지 → 골반 → 척추 → 팔
한 스텝 순서(step 1112-1148, 바뀌는 곳만 굵게): updateHeading(의도만) → skill.update → updateBodyPose(ψ_p·cT 목표, 그대로) → driveBalance(받침·밀기 그대로, **닻 yaw 0·닻 틀 = 실제 골반 yaw**) → gait.pinFeet(**legs 가지: N×6/7 한계**) → applyPose(poseLegs: **딛은 다리 엉덩이 목표에 Δψ 하중 몫**; 척추 목표 그대로) → driveSword → offHand → driveJoints(**엉덩이 y 축 σ 포화·속도 목표 0, 척추 y 축 속도 목표 0·d 가지**) → elbowGravity → trackBlade → **chainLedger(시뮬 전용, 측정만)**. 모든 새 줄은 `BODY.chain === 'legs'` 가지 안, else 는 옛 줄 그대로(바이트 동일, §5 G1).

### 2.1 단계 ① 발 지지 — 땅이 받칠 수 있는 돌림힘 (C 에서 측정만 접붙임)
- **물리**: 골반을 돌리는 토크의 반작용은 결국 두 발의 수평 마찰 힘쌍 + 발바닥 자유 모멘트다. 어림: τ_땅 ≤ μ·min(N_F, N_B)·d_feet + 2·μ·N·0.05. μ 0.9·d_feet ≈ 0.55~0.59 m, 받침 0.2 에서 발당 N ≈ 295 N → **≈ 150~180 N·m**(받침 0 이면 ≈ 225, wF 0.8 로 한쪽에 쏠리면 ≈ 73). 이 수는 **어림이지 관문 숫자가 아니다** — W1 이 접촉 임펄스로 재기 전엔 관문에 쓰지 않는다(심사 2 조건).
- **비틀기 토크의 실제 싱크**(심사 2 지적): 엉덩이 y 토크의 반작용 중 '순수 비틀기' 몫은 허벅지 → 무릎 경첩(비틀기 잠김) → 정강이 → 발목 공 관절(y ±0.3, 모터 700×gain) → 발 yaw 핀(gait.js:1013-1024: 한계 μ·N_f·0.05 ≈ **13~16 N·m/발**)으로만 땅에 간다. 골반이 돌면 엉덩이 중심이 수평으로 움직여야 하므로 그 몫은 엉덩이 공 관절의 **힘**으로 허벅지를 밀어 발 수평 마찰 힘쌍(위 150~180)으로 간다. 둘 중 어느 길이 얼마나 받는지는 설계로 정할 수 없고 **W1·W2 가 잰다**: '엉덩이 y 토크 중 골반 각가속도로 간 몫' ≥ 0.5 가 W2 완료 조건(§6).
- **코드 자리**: 새 힘 없음. legs 가지에서만 pinFeet 한계 `pinMu·Nf`(gait.js:980-981)에 접촉 N ×6/7 (Rapier 0.19 (n+1)/n 과대 보고 교정, support_optimum §2 와 같은 식 — 엔진 보고 오차 교정이지 상한 아님, 확인표 127). 장부 열: 발 하중 N_F·N_B(×6/7)·wF·마찰 예산 μ·min(N)·d_feet·핀 미끄러짐(pinC 이동)·발 yaw 핀 포화 스텝.
- **지우는 강제**: 없음(받침 0.2·catch on·걷기 밀기는 사장님 10/1 상자 그대로). C 의 S1(보이지 않는 fy 를 발바닥 점에 싣기)은 **금지** — 접촉 N·μN·발 하중 p10·wF 를 부풀려 이 단계의 측정 전부를 오염시킨다(심사 1 실패 모드 C).

### 2.2 단계 ② 골반 — 닻 yaw 0, 엉덩이 비틀기 근육이 돌린다
- **지우는 강제 셋**(O1 의 자리):
  - K1 닻 yaw 축 모터 **미설정**(raw 5 에 `jointConfigureMotorModel/Position` 을 부르지 않음; fighter.js 닻 관절 생성·driveBalance). **10/7 정정**: 0·0 설정은 자유가 아니라 경성 속도 잠금이고, generic(축 (1,0,0)) 관절은 raw 3 = x·4 = z·5 = y(연직)라 10/2 W1b 가 0·0 으로 둔 raw 4 는 yaw 가 아니었다(한 관절 시험, 디렉터 작업 공간 a021; `docs/dev_exchange/reviews/2026-10-07-saetbyeol-experiments.md` ⑥). 닻 회전은 **실제 골반 yaw**(측정값)를 따라 pitch·roll 기준 틀 노릇만 한다(1822 의 `heading + pelvisYawOffset` 목표를 legs 가지에서 쓰지 않음). 닻 yaw 감쇠 330(골반 2.3 rad/s 에서 ≈1.7 kW 보이지 않는 제동기)도 함께 사라진다. **0 아니면 오늘 그대로** — 'k 0·d 유지', '상한 둔 닻 yaw'(B s0.5) 같은 중간 형태는 모두 금지(질량 무한 몸체가 내는 토크는 크기와 무관하게 반작용이 땅으로 안 간다).
  - K2 heading(687-699, 2.4 rad/s 직접 쓰기)은 **의도**(입력 틀·목표 기준)로만 남는다. 쓰러짐 가지(701-705)는 그대로.
  - K3 bodyPose.pelvisYaw(aimRaw 를 34 rad/s 로 쫓는 2차 필터, 941)는 **목표**로만 남는다. 읽는 구동기는 엉덩이 하나.
- **목표식**(B §2.3 접붙임): 의도 ψ* = heading + pelvisYawOffset(지금 닻 목표 1822 의 식 그대로, 새 식 없음), 실제 ψ = 골반 몸체 yaw, Δψ = wrap(ψ* − ψ). 딛은 다리 l 마다 legIK 가 만든 허벅지 목표 q_hip,l(gait.js:921-923, 실제 골반 기준)을 **q_hip,l\* = R_y(−w_l·Δψ) · q_hip,l** 로 바꾼다. w_l = 그 다리 하중 몫 N_l/ΣN(gait `legs[k].Nf`, 걸러진 값). 내딛는 발은 오늘 그대로. 두 발이 다 딛으면 토크가 N 비례로 나뉘고(A R10 의 '나눔'을 식에 넣음), 한 발이면 그 발 하나 — 한 발로 설 때 골반이 잘 못 도는 것은 사람과 같다.
- **구동기**(심사 1·2 가 조건으로 단 접붙임, A 의 '직접 토크 쌍(manualMuscle 꼴)' 문장은 **삭제**): 엉덩이 y 축은 **엔진 암시 모터를 그대로 두고** 스텝마다 낼 토크를 미리 셈해 k·d 를 함께 줄인다.
  - τ_pd = k·e_y − d·ω_rel,y (e_y = 목표 − 현재 y 각, ω_rel = 허벅지 − 골반 각속도의 y 성분; 속도 목표 **0**)
  - τ_cap = j.max × mus (기존 엉덩이 상한 560 'asis' / 208 'human' × driveJoints 의 mus, 새 수 없음)
  - σ = min(1, τ_cap / |τ_pd|) → `jointConfigureMotor(h, y축, t_y, 0, k·σ, d·σ)` (k·d = 기존 1800·160 × 딛은 다리 gain 2)
  - 감쇠항까지 상한 안에 들어오고(오늘은 d·Δω 가 j.max 밖, 2067-2074), 암시 해라 허벅지 관성 0.02 kg·m² 에서도 안정하다(명시 PD 는 d < 2I/dt ≈ 4.8·k < 4I/dt² ≈ 1150 이 한계 — fighter.js:2152 주석과 같은 이유). 목표 끌어 붙임 maxErr(2043)는 그대로 둔다(스프링 몫 상한). x·z 축은 오늘 그대로(다리 IK 가 체중을 받친다). 실제 낸 토크는 τ̂ = kσ·e_pre + dσ·(0 − ω_post) 로 장부에 **추정값**이라 적고(엔진이 관절 임펄스를 안 내줌), 골반 각가속도 × I 와 교차 검산한다.
  - **포화율** σ<1 인 스텝 몫을 장부 열로(B 접붙임) — '예산 부족'(포화율 높은데 오차 안 줄음)과 '감쇠'(낮은데 떨림)를 가르는 유일한 지표.
- **크기 감**(어림, 측정 전): 딛은 다리 뺀 몸 수직축 관성 ≈ 2.6~2.8 kg·m². 땅 ≈ 150~180 N·m 가 상한이면 α ≈ 55~65 rad/s², 40° 에 ≈ 0.15 s, 골반 ω 최고 290~400 °/s(봉투 크게 321, 사람 최고 714 안), 출력 ≈ 1 kW. 닻은 지금 이 일을 상한 없이 0.03 s 에 한다(골반 6925 °/s 기록).
- **돌려 딛기**: |ψ* − 발 yaw| 가 커지면 기존 yawTol·settle 걸음이 발을 돌려 딛는다. limitTurn(maxTwist 0.9)은 heading(의도) 변화에만.

### 2.3 단계 ③ 척추 — 늘었다 되튀는 탄성 (A 그대로, σ 길만 공유)
- **목표식 그대로**(applyPose 2018-2022): twist = chestYaw − pelvisYaw, 복부 0.45·가슴 0.55, 한도 ±45°(HUMAN.spineTwist, 확인표 108). 가슴 yaw 목표 = updateBodyPose v2 가지 cT(901-902).
- **바꾸는 것 둘(비틀기 y 축만, legs 가지)**:
  (a) 감쇠항 속도 목표 0: driveJoints 2072-2073 의 `v = clamp((_rv − prev)·inv, ±15)` 를 척추 y 축에서 0 → 감쇠는 골반 상대 각속도에만 걸리는 **수동 감쇠**(에너지를 넣지 못함). 스프링 몫은 오늘처럼 maxErr 로 j.max(500/440) 안.
  (b) 감쇠비 사람 띠: 윗몸(가슴+머리+두 팔+칼) yaw 관성 I_up ≈ 2.0 kg·m²(A 부록 A). 오늘 ζ = 160/(2√(1600·2.0)) ≈ 1.41(가슴)·180/(2√(1800·2.45)) ≈ 1.36(복부) = 과감쇠 → 골반·가슴이 9 ms 차로 함께 돈다(진단 R2 출시 측정). **ζ 0.5 후보** → d_가슴 ≈ 57·d_복부 ≈ 66 N·m·s/rad(확인표 125). 강성(직렬 847 N·m/rad → ¼주기 ≈ 76 ms, 봉투 가슴 늦음 −58~−33 ms 와 같은 자릿수)은 그대로(확인표 129, 정보).

- **되튐이 생기는 까닭**: 모터가 아니라 **골반이 먼저 가속되고 윗몸이 관성으로 처지는** 결과다. ②가 있어야 ③이 보인다. R4(±45° 한도 덜컥)가 나면 ζ 0.7 → 오늘 값으로 되돌리지, '쿠션·소프트 한도' 같은 새 조건은 넣지 않는다.
- **B 의 '명시 척추'(e 를 안 자르고 토크만 자르는 참 탄성)는 가져오지 않는다**: 둘째 탐색판 뒤 측정으로 되튐이 부족하면 그때 후보(confirm 전).

### 2.4 단계 ④ 팔·손목·칼 — 보정 v2 그대로
- driveSword(2165-2213) → armIK(2392-2424): 손 목표는 가슴 틀(rawHand), 실제 가슴 틀에서 푼다. 가슴이 물리로 돌면 손이 실려 간다 — 몸이 칼끝에 보태는 길. 칼끝 방향 서보(60·θ, 상한 22 N·m·Hill), 보정 v2 ①(날 맞춤)·③(되돌아옴 pad*), 끝점 겨눔 ② 끔, 사람 관절 한도·자기 몸 충돌(humanLimits) 모두 그대로.
- 빈손↔폼멜 스프링(1500·max 250 N) 그대로 — 내부 힘이라 잔차에서 상쇄. 가상 '공통 작용점'(샛별 A-013) 만들지 않음.
- **명시·측정만**: 손목 반작용의 아래팔 축 몫이 가슴에 직접 가는 길(2381-2385)은 어깨·팔꿈치 80 N·m 를 우회한다 → 장부 열로 적고(확인표 151), 바꾸는 것은 측정 뒤.
- 걷기·받침 0.2·catch·걸음 밀기 240 N 그대로. **skill.lunge**(622-627·720-724, 매 베기 앞걸음 H1-A 의 자리)는 legs 가지에서 **끔**(확인표 126, 진단 §8 Q2 의 '당분간 끔') — 걸음은 균형(capture point·stumble·settle)에서만. 대안 **C 의 거리식 걸음**(fwd = clamp(d − reach_eff, 0, maxStride), 발사는 기존 '새 휘두름' 사건, reach_eff = 0.53 + 칼자루 + 칼날 − 0.11 ≈ 1.60 m 기하)은 확인표 156 으로 나란히 두고 둘째 탐색판 URL 칸에서 사장님이 고른다(§9 Q2). AI 의 gait.requestStep(ai.js:1501-1504)은 그대로.

## 4. 손가락 입력 — 감기(A) 기준, 호 당김 없이
- **바뀌지 않는 사슬**: 패드 Δ → handOffset(main.js:1358-1368, 멈칫 중 0.25 배) → 가죽끈 0.02 m(skill.js:576-588) → aimRaw(v2, 이어 베기 없음)/aim(14/24 rad/s) → rawHand 가슴 틀 깊이 매핑(fighter.js:170-174) → armIK 어깨·팔꿈치 목표 + 칼끝 방향 guardDir(heading 틀) → 되돌아옴 ③ pad*(손 뗌 0.25 s 뒤, 1.2 m/s) → 탭 찌르기 thrustPose. 긋기(B)는 깃발 뒤 잠듦. 분류기·결심 S·위상 φ·계획기 **없음**.
- **손가락이 주는 것 셋**: ① 손 끝점(가슴 틀) ② 칼끝 방향 ③ **넘침각 ex**(corrTrunkTurn 783-860: 어깨 쐐기 −45~130°·팔 0.565 m 밖으로 패드가 가면 몸통이 그만큼 돌아야 닿는다 — 기하, 새 수 없음). ③ 이 곧 '얼마나 감았나'. 패드 가장자리(0.62)에서 몸 앞 가로지르기는 어깨 0.2 m 에서 0.72 m 라 늘 넘친다 = 큰 감기.
- **빠르기는 주지 않는다**: ex·turn 은 목표 ψ*·cT 로만. 손가락이 0.1 s 에 패드를 가로질러도 골반은 땅이 허락하는 α 로만 돈다. 손은 24 rad/s 필터로 손가락 박자를 지킨다 — 몸은 늦게 오고 그만큼 칼끝에 무게를 더한다.
- **폰 짧은 획이 닿는 길(호 당김 없이)**: (a) 감기 끝(패드가 쐐기 밖)에서 골반·가슴이 ex 만큼 감겨 있고, (b) 긋는 순간 ex 가 부호를 바꾸며 풀리면 가슴 틀이 20~40° 돌아 **손이 가슴 틀에 붙어 그만큼의 호(0.5 m × 0.5 rad ≈ 0.25 m)를 물리로 더 그린다**(옛 호 당김 ≤ 0.15 m 보다 큼). 쐐기 안에서만 노는 짧은 획은 팔 베기 = 사람의 '작게'. 패드 감도(main.js:1358 배율)·몸통 몫 0.35(보정 v2 여쭘 18)는 입력·나눔 값이라 사장님 몫 — 설계는 올리지 않는다.
- **오독**: 분류기가 없으니 '감기로 읽힘/안 읽힘' 자체가 없다. ex 0 이면 팔 베기, 넘치면 몸 베기 — 연속.
- **AI**: handOffset 을 7.5~13 m/s 로 직선 이동(ai.js:1340-1364). 같은 몸이라 AI 골반도 다리로 돈다 → 세기는 W2 배터리로 다시 잰다.
