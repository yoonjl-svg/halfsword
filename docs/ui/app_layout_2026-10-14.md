## 해상도 점검 (앱과 웹)

캔버스 내부 크기와 CSS 크기가 어긋날 수 있는 길:

1. **resize 이벤트가 늦거나 빠질 때** — 전에는 `resize()`(캔버스)와 `layoutDraw()`(카드)가 `window` 의 resize 이벤트에서만 다시 쟀다. 아이폰 홈 화면 앱은 처음 열 때·돌릴 때 innerHeight 와 resize 이벤트가 늦게 바뀌는 일이 알려져 있다.
2. **innerWidth/innerHeight 가 실제 상자와 다를 때** — 캔버스는 CSS 로 화면 가득(#game fixed inset 0)인데 내부 크기는 innerWidth/innerHeight 로 정했다.

고친 것 (필요한 것만):

- `resize()` 는 캔버스의 실제 CSS 상자(`canvas.clientWidth/clientHeight`)로 잰다. `ResizeObserver` 가 캔버스 상자가 실제로 바뀔 때 다시 부른다 (window resize 듣개도 둔다 — 화면 배율만 바뀌는 때).
- `layoutDraw()` 는 #draw 상자 높이로 재고, `ResizeObserver(#draw)` 가 상자가 바뀌면 다시 부른다 (카드가 처음 보일 때도 한 번 더).
- orientationchange · pageshow · visualViewport resize 는 넣지 않았다: 어느 경우든 화면 상자(캔버스 · #draw)가 실제로 바뀌면 ResizeObserver 가 잡는다. visualViewport 만 바뀌는 경우(손가락 확대 · 자판)는 게임이 쓰는 상자를 바꾸지 않는다.

숫자 (크로미움, 아이폰 흉내 dpr 3 → pixelRatio 2):

| 화면 | canvas.width×height | CSS × pixelRatio | 맞음 |
|---|---|---|---|
| 844×390 · 932×430 · 844×340 · 932×370 · 390×844 | 1688×780 · 1864×860 · 1688×680 · 1864×740 · 780×1688 | 같음 | 전·후 모두 맞음 |
| PC 1280×720 (dpr 1) | 1280×720 | 같음 | 전·후 모두 맞음 |

이벤트가 정상이면 전에도 맞았다. 그래서 **resize 듣개를 일부러 막고 크기만 바꾸는 흉내**(`window` 의 resize 를 먹는 시험 스크립트)를 했다:

| 흉내 | 전 (main) | 후 |
|---|---|---|
| 844×430 에서 카드를 띄운 뒤 844×390 으로 (이벤트 없음) | 캔버스 1688×**860** / CSS 844×390 → 세로 배율 2.205 (그림이 위아래로 눌림). 카드 228×342 가 **y 47–389** — 첫 카드가 둘째 줄을 덮음 | 캔버스 1688×780 (배율 2·2). 카드 156×234, y 78–312 |
| 390×844(세로)에서 띄운 뒤 844×390 으로 (이벤트 없음) | 캔버스 780×1688 / CSS 844×390 → 배율 0.92 · 4.33 | 캔버스 1688×780 (배율 2·2) |

- 첫 줄 흉내의 '전' 그림(`app_layout_stale_before.webp`)은 사장님 스크린샷과 카드 크기·자리(x 66–294 · y 47–389)가 **같다**. 카드 높이 342 는 카드를 잰 순간의 화면 높이가 최종(390)보다 컸고(≥ 430) 그 뒤 다시 재지 않았을 때만 나오는 값이다.
- **확정**: 이벤트 없이 상자가 바뀌어도 이제 캔버스·카드가 다시 맞춰진다 (위 흉내). 카드 높이 상한(0.6)과 둘째 줄 미리 비움으로, 다시 재기 전이라도 카드가 둘째 줄을 덮지 않는다.
- **추정 (확정 못 함)**: 아이폰 앱에서 카드를 잰 순간 화면 높이가 왜 컸는지(돌리는 중이었는지, 앱이 처음 열릴 때 높이가 늦게 바뀌었는지)는 크로미움으로 똑같이 흉내 낼 수 없어 모른다. '웹과 해상도가 다른 느낌' 이 캔버스 배율 어긋남(그림이 눌림)이었는지, 단지 앱이 주소창 없이 더 커서 카드가 커 보인 것인지도 기기에서 확인해야 한다 — 다음 판을 아이폰 앱에서 열어 카드 크기·그림 비율을 보면 갈린다.
